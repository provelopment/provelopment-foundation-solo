# Foundation Solo — plan-next (Next Candidate)

**Candidate:** `R02.B` **remaining work** — Stage 02, One-Entity EFS identity and publication authority. A single non-authorizing candidate; readiness only, never an instruction to execute. `R02.B`, `R02.C` and Stage 02 all remain **open**.

**Objective.** Implement the part of `R02.B` that both accepted slices deliberately left unproven: capability-confined, no-follow filesystem acquisition of the declared source candidates; verified rather than merely reported absence; resolved-source collision refusal across aliases, hardlinks, separators and case; an owned immutable snapshot of the selected body; complete selected-body validation for both body kinds; and the outstanding parser, schema, Unicode, URL, property and visibility conformance proofs. Grounded in `ARCHITECTURE.md` §1.5–§1.6 and §6.2B–§6.2C.

**Already delivered, and not this candidate.** Two bounded slices are published and independently `ACCEPT`ed; this candidate must not re-describe, re-claim or rebuild either of them.

- The first slice — the inert `ParsedManifestCandidateV1` strict parser and the pure lexical `pages/` locator — was published at `cf15cd5` / tree `1ba7650` and accepted at HEAD `ea9f9fe`.
- The second slice — the provisional JSON-first observation and pre-selection policy in `solo-domain` plus the inert selected-body byte preflight in `solo-adapters` — was published at `4fa9b51` / tree `f8561f12` and accepted at report HEAD `1cd2751` / tree `bb718fb8`, with both hosts green in run `42569678884`.

That accepted policy decides which *supplied* observation wins and refuses invalid *selected* bytes. It opens no file, proves no absence, forms no snapshot, selects no effective source and confers no publication authority: `OBSERVATION_IS_FILESYSTEM_PROOF`, `PROVISIONAL_CHOICE_IS_FINAL_SELECTION` and `CONTENT_VALIDITY_PROVEN` are all `false`, and both authority accessors return `false`.

**Satisfied prerequisites.** The accepted slices supply everything a file reader must consume rather than reopen: a closed five-key manifest root with duplicate-member refusal and exact `schemaVersion: "1.0.0"`; bounded inert `properties`; validated `sourceCandidates` whose logical duplicates are already reserved even when the referenced path is absent; a lexical `pages/` locator; a deterministic read order that separates declared `Absent` from a named failure without converting one into the other; and a closed body root with 2 MiB JSON and 1 MiB Markdown envelopes, strict UTF-8 without a byte-order mark, depth-wide duplicate refusal and bounded `title`, `summary` and `blocks`. The four-crate inward-only graph is green on both hosts with `packages=4 targets=18 files=30 edges=24`, and `Cargo.lock` is unchanged at 15 packages.

**Readiness.** `READY` on that recorded evidence, with one disclosed forward dependency rather than a hidden one: the native mechanism for descriptor- or capability-based no-follow confinement is not yet chosen, and selecting it — or adopting any new vetted component — requires its own separate Owner-issued order and security review, including a per-host story for both CI operating systems. That is an authorization dependency to be satisfied by that order, not an unmet prerequisite of this candidate. `std::fs::canonicalize`, string-prefix tests, post-open `metadata` alone, symlink-following reads, guessed aliases and caller assertions are all excluded in advance as insufficient. **No implementation is authorized here.**

**Bounded future deliverables.** Capability-scoped access confined to the declared content root; no-follow, no-symlink-escape and no-directory-substitution containment proven per host; resolved physical collision refusal across case, separators, hardlinks and aliases; exactly one effective source per representation with JSON preferred and a recorded reason; absence distinguished from read, parse and permission error without fallback prose; an owned snapshot that cannot change beneath the reader; complete validation of the selected body for both kinds, including the Markdown grammar and raw-HTML refusal that the inert preflight deliberately omits; and conformance proofs for the remaining declared parser, schema, NFC/Unicode, URL-safety, property-projection and visibility rules. Applicable architecture, refusal and security gates only — no route, visibility serving, rendering, UI, provider, release, new dependency, new package or application feature is implied.

**Future acceptance and refusal criteria.** A path escaping the content root by any means, an unreadable or non-UTF-8 body, a traversal, separator, case, alias or hardlink resolving to an already-claimed Page, a missing file where an error is required, an error where absence is lawful, two candidates of equal precedence and any undeclared read must each be refused or explicitly classified, never silently resolved. An existent invalid JSON body must never fall back to Markdown; a reported absence must never be promoted to proof of absence; selected and reserved sources must never merge or diverge; and a successful read must never by itself publish. The candidate is complete only when each of those cases has an executable refusal or classification test running on both hosts, and the architecture checker still reports the approved four-crate package set and edge count.
