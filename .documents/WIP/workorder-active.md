**D2 candidate: a private per-file Linux COW clone.** The currently pinned, already installed, Linux-only `rustix =1.1.5` with feature `fs` has safe `rustix::fs::ioctl_ficlone(destination_fd, source_fd)` and `openat`/`OFlags` interfaces. The Linux `FICLONE` kernel contract describes an **atomic clone relative to concurrent writes**, with subsequent source and clone writes separated by copy-on-write. The complementary `O_TMPFILE` contract creates an **unnamed inode** under a directory on that filesystem; `O_EXCL` in combination with `O_TMPFILE` prevents later linking it into the namespace. These facts justify a *candidate*, not advance ACCEPT. Authoritative references to inspect at the exact installed versions: Linux `FICLONE(2const)` https://man7.org/linux/man-pages/man2/FICLONE.2const.html ; Linux `open(2)` `O_TMPFILE` https://man7.org/linux/man-pages/man2/open.2.html ; pinned `rustix` safe API https://docs.rs/rustix/1.1.5/rustix/fs/fn.ioctl_ficlone.html . If the pinned API/source does not support the proposed safe call and flags, STOP before modifying a permanent source file.

**Exact Linux flow to attempt, in the existing `source_read_native.rs` Linux `sys` module only:**

1. Hold the existing explicitly trusted, verified root **owned fd** and the existing confined source **owned fd** opened with `openat2` (`BENEATH | NO_SYMLINKS | NO_MAGICLINKS | NO_XDEV`), preserving by-fd type, identity and hardlink checks and logical reservations. Neither an untrusted string path nor `canonicalize` may replace these handles.
2. Require the opened source to be a plain regular file and enforce the existing per-kind JSON 2 MiB / Markdown 1 MiB size/byte bounds, including source change while obtaining the clone. The root and candidate must be within the same intended mount, and the anonymous destination's by-fd device/mount relationship must be verified. An unsupported or ambiguous mount is refusal. Do not read the source's mutable body bytes first.
3. Obtain a **new unnamed, process-private destination inode** on the **same confined source filesystem**, using the trusted root (or verified capability-relative directory) with `O_TMPFILE | O_EXCL | O_RDWR | O_CLOEXEC`, restrictive mode, and safe `rustix` ownership; do not create a named temp file or a different-filesystem scratch copy. No `linkat`/`rename`/`persist`, no leaked destination fd, no path into product content/drafts/generated/public namespaces and no retained inode after its last fd closes. If `O_TMPFILE` is unsupported or creation errors, refuse.
4. Call the safe `ioctl_ficlone(unnamed_destination, pinned_source)` **once**. On an unsupported filesystem (`EOPNOTSUPP`, `EINVAL`, `EXDEV`, `ENOSYS` and other actual non-support), insufficient privileges, ambiguous result, interrupted/failed clone or any source/destination identity mismatch, **fail closed**: do **not** fall back to `copy_file_range`, `read`/`write` copying, `std::fs::copy`, `mmap`, advisory locking, sleep/retry as proof, a path-based second open, or acceptance on matching timestamps. Distinguish real unsupported behavior from ordinary I/O and resource exhaustion in the typed refusal, without leaking host paths.
5. Read **only the successfully cloned anonymous inode** with bounded safe descriptor I/O. Confirm the full clone byte length and exact transferred length; recheck the clone and source handle facts as appropriate. Source modifications **after** the atomic clone must **not change the cloned bytes**. Any source-side mutation actually observed during the applicable probe/clone/read/validation window must invalidate that attempt as `SNAPSHOT_CHANGED`; an immutable clone never excuses an observed change. A source mutation observed between probe and clone must likewise remain `SNAPSHOT_CHANGED`. An undetectable edit between observations must never be presented as *detected* by metadata, and this per-file snapshot must not be represented as the later global candidate-invalidation proof. Read results must be immutable owned bytes; only the selected source member's body may be cloned/read. No external writer is given a handle to the clone. The FD is RAII-closed on success, error and panic.
6. Make the smallest safe-wrapper change needed to carry this new Linux read path. No OS-specific type enters `solo-application` or `solo-domain`; the existing outward port and Windows native traversal remain unchanged except for separately required Windows writer-exclusion tests. Per-file immutable bytes are **not** an atomic multi-file/whole-candidate publication snapshot. `SOURCE_READ_PROVES_GLOBAL_SNAPSHOT`, `SOURCE_READ_GRANTS_PUBLICATION_AUTHORITY` and every existing publication authority accessor **remain false**.
