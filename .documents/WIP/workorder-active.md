## 5. Binding minimal Linux native code contract

The native file is **not a process supervisor**. It may contain only a private typed snapshot and safe wrapper for observing the **current process**'s existing `RLIMIT_AS` and `RLIMIT_CPU` soft/hard ceilings; no external arguments, mutations, child launch, process IDs, paths, handles or evidence-output files. The only permitted Linux FFI function is `libc::getrlimit` called with `libc::RLIMIT_AS` and `libc::RLIMIT_CPU`. Selectors are compile-time fixed: there is no public or arbitrary-resource API. `libc::rlimit` is the only raw C value read from these calls. Do not introduce `libc::setrlimit`, `setsid`, `kill`, `prctl`, `fork`, syscall wrappers, `Command` or an OS process for this work order.

Prefer one **small** `#[cfg(target_os = "linux")] mod linux { … }` within the new native file. Put `use libc` and every `unsafe` block under this **positive nested Linux module gate** so both the AST checker and independent source scanner inspect the real file and can prove its target. Do not rely on `#![cfg]` alone, comments, file name, `cfg_attr` alone, a generic `unix` gate, or a source-checker exemption. A safe `pub(crate)` wrapper may return `Result<NativeLimitReadbackV1, NativeReadbackRefusalV1>` (or equally narrow private types); refusal is typed and does not leak OS text, paths, secrets or raw worker input. Use `MaybeUninit<libc::rlimit>` correctly: write only through the kernel pointer, check zero return before `assume_init`, explain the exact invariant next to each `unsafe` block. `libc` is already in the locked graph, but this is a new **direct Linux-only dependency edge**, not a new package.

Unit tests in the **same new native source file** must run as part of the original `cargo test --workspace --all-targets --locked` on Ubuntu and prove at least:

- `N076-01`: actual `getrlimit(RLIMIT_AS, …)` and `getrlimit(RLIMIT_CPU, …)` both return successful typed observations; include explicit exact selectors in the test name/trace. No fabricated struct or mock return is accepted as this proof.
- `N076-02`: the soft/hard values are reported separately with the raw `rlim_t` range preserved, including `RLIM_INFINITY` without truncation, false finite-limit inference or changing any process limit. Repeating the read on the same process gives consistent observations; do not assert a fixed CI-host limit value.
- `N076-03`: any failed kernel call would be a typed refusal and cannot produce a partly initialized successful observation. Avoid root privileges and unsafe fault injection; this can be proved by the direct code path plus a pure helper test, and must be described as a source-path proof rather than an actual injected syscall failure.
- `N076-04`: Windows compiles with no Linux-native module linked and no Linux readback claim. Normal `rust-verify` Windows job passes all unchanged suites and guard tests; do **not** report Windows OS-containment or an executed Windows kernel test.
