## 4. Required narrow implementation contract

**4A — Closed public boundary.** In the safe façade expose exactly one named, fixed harmless smoke operation (`run_internal_linux_limit_smoke_v1` or a comparably precise name) returning a closed `Result<SmokeObservationV1, SmokeRefusalV1>`, plus the minimal internal child readback helper needed by the CLI. No API may accept an untrusted executable path, arbitrary `Vec<OsString>`, shell text, media bytes, manifest, caller-chosen limits, environment overrides or destination path. The Linux implementation may resolve its *own running* executable with `std::env::current_exe()` as an expressly limited **trusted-test** assumption; refuse absent/unusable identity and do not claim this prevents executable replacement or proves a production trust root. On Windows or unsupported OS return a stable `HOST_UNSUPPORTED` refusal **before any child creation**. No Windows Job Object, Windows child or Linux native module inclusion there.

**4B — Native pre-exec boundary.** The actual `unsafe` `CommandExt::pre_exec` registration, if required by the compiler, must reside **only** in `media_worker_host_native.rs`, together with the native Linux calls. Use `setsid()` to put the child into a new session/process group, and `setrlimit(RLIMIT_AS, ...)` / `setrlimit(RLIMIT_CPU, ...)` with **both soft and hard** values set to 536870912 bytes and 10 seconds, respectively. These operations must happen in `pre_exec` **before the image is executed**; a parent-side `setrlimit` or `ulimit` command does not count. The post-fork pre-exec closure must use only operations appropriate to an async-signal-safe fork child: no allocation, locking, formatting, logging, Rust I/O, file scanning, path resolution, `getrlimit` observation, panic/unwrap, shell or thread creation. Set up any command/path/pipe structures **before** forking; return a fixed failure on any required syscall failure, without launching the workload or claiming partial limits. If the pinned APIs cannot meet these preconditions, STOP rather than introducing unapproved native paths or making a false async-signal-safety claim. Preserve all accepted `N076` kernel-readback tests and `MaybeUninit` safety invariants byte-for-byte or behavior-for-behavior.

**4C — Exact internal CLI modes.** Reserve one fixed internal flag `--internal-media-host-probe-v1` with exactly one sub-mode token `parent` or `child`, no extra argument, no alternative form and no public help/completion exposure. Dispatch before ordinary `bootstrap-preflight` parsing; any wrong spelling, missing sub-mode, duplicates, extra tokens or unsupported OS is a refusal, not a fallthrough that silently executes any workload. The `parent` mode invokes the fixed safe façade. The `child` mode performs **only** its own fixed `getrlimit` readings and observes the own pid/process-group identity (via a Linux-only native query if truly necessary; document and gate it); it verifies both soft and hard values **exactly equal** the profile before printing anything usable. It never allocates a stress buffer, spins, sleeps deliberately, spawns descendants or emits an output/staging file. A direct normal unsupervised `child` invocation on the real test runner must not produce valid success evidence. These modes are an internal harness, **not** a security credential: a separately configured process might independently meet the profile, and the test must not claim cryptographic parent attestation.

**4D — Bounded parent observation.** Use a single fixed trusted child with closed stdin, bounded captured stdout and stderr (suggested maximum **1024** and **512** bytes, respectively), exact version marker / fixed schema with no unknown, duplicate, partial, trailing or nonnumeric fields, and an actual finite 15,000 ms parent watchdog. Require normal zero exit, full readback agreement with the fixed Linux caps, observed own pid and `pgid==pid` for `setsid` where reported, and zero writable staging/promotion. Any mismatch, malformed evidence, failure to capture, premature child exit, failed process launch/pre-exec, timeout or unreaped leader is a typed refusal. Avoid blocking forever on an output pipe: prove how the implementation reads/caps the pipe and enforces the watchdog even when output is malformed or not flushed. On all paths it must close owned pipe handles and reap the **single smoke child**; if a child cannot be reaped, stop the test and mark failure. A child is deliberately forbidden to spawn descendants in this order, so **process-tree/group-sweep proof is not claimed** — it belongs to the next order, not a hidden success of `setsid` alone.

**4E — Closed refusal vocabulary and outputs.** Use stable types covering at least `HOST_UNSUPPORTED`, `HOST_EXECUTABLE_UNAVAILABLE`, `HOST_LIMIT_UNAVAILABLE`, `HOST_SPAWN_FAILED`, `HOST_WALL_TIMEOUT`, `HOST_EXIT_ABNORMAL`, `HOST_OUTPUT_INVALID` and `HOST_REAP_FAILED`. Keep reason text fixed and free from OS environment strings, source contents, process secrets and arbitrary paths. Document exactly how a `pre_exec` failure is classified (some `Command::spawn` errors cannot distinguish a rejected limit from exec failure without further evidence); do **not** invent OS-specific proof for a category that cannot be discriminated. Do not log or echo raw child stderr; no partial success line can appear before normal exit and complete parent validation. Parent mode may emit **one** fixed accepted evidence line on success and no evidence on refusal; it never upgrades existing public product contracts.

**4F — Exact preserved trust boundaries.** No filesystem content-reading dependency or CLI behavior changes outside the fixed internal mode. No source/manifest/publication input enters the supervisor. The media worker port remains unimplemented by a real decoder; `MEDIA_WORKER_GRANTS_PUBLICATION_AUTHORITY_V1` and `MEDIA_WORKER_PROVES_MEDIA_CORRECTNESS_V1` remain `false`. `RLIMIT_AS` bounds *virtual address space*, not RSS or aggregate child-tree memory; `RLIMIT_CPU` is CPU time, not elapsed wall time.
