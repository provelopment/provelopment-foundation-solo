## 4. Required bounded code behavior

### 4A. One authoritative inventory derived from existing validation

Use the **validated** `PropertyResolutionCandidateV1` as sole input; do not accept raw untrusted JSON, partial declaration arrays, a caller-supplied arbitrary owner list, URL/route/locale/geography, filesystem directory, platform catalogue, or a hand-built fake graph in the production entry point. The candidate already validates complete EFS membership and **all owners** before selecting a target. It is a nonpublishing property candidate and remains so. Do not reinterpret `project_public_properties_v1` as the inventory: public projection must omit `internal` and suppressed values, whereas the future asset-byte gate needs **every independently authored graphic reference**, including invisible ones.

For each **real** qualified owner in `input().owners()` parent-first, get its optional validated declaration from `input().declaration_for(owner)`. Inspect each registered graphic-key declaration in the stable `PropertyKey::ALL` registry order (or prove a single equivalently canonical order), then enumerate the original `currentContext` entry array in zero-based authored index order. For each real graphic typed value, record exactly one immutable obligation. Do not add a new obligation for a repeated value merely because it appears in a child effective inherited collection. If the same typed source was independently authored by two different owners/roles/indices, represent **both** obligations with their distinct owners and local indices, not a collapsed dictionary entry. A literal `"none"`, absent graphic key or local `suppress` without a new local graphic value contributes no new declaration obligation; `suppress`+new authored value contributes only the new local obligation. An ancestor's previously authored obligation stays in the *global authored-inventory* even if a descendant's `suppress` removes it from that descendant's effective values.

The typed inventory entry must expose, without allowing callers to mutate it: (1) **declaring original** `QualifiedOwnerV1`; (2) registered `PropertyKey` restricted to graphics; (3) zero-based `localIndex`; (4) original `Exposure`; (5) original `AssetReferenceV1`, carrying its explicit `AssetNamespace` and unchanged `reference` text. Use owned validated values or immutable well-bounded borrows; no duplicate string authority, route- or filename-derived owner, alternate graphic key, introduced property tier, or exposure promotion. The inventory's ordering and equality must be stable across repeated calls and independent of requested target representation. The only aliasing allowed is immutable typed reference reuse, never mutable inherited data.

Maintain a separate `declared` obligation inventory and an existing `effective`/public projection as **different concepts**. The inventory must never choose an effective layer, filter out a private reference, claim a source is safe, or return the bytes of an asset. The existing effective singular maximum, background four-layer maximum, duplicate exact reference refusal and post-suppression empty result remain enforced by the accepted property resolver. The inventory is downstream of those gates, so an invalid whole-graph declaration produces no inventory even if the selected representation is healthy.

### 4B. Namespace, pinned library and fail-closed nonpublication

An `entity` reference remains tied to the **one** Entity's owner-approved asset source root, without implying it can be found beneath an EFS Page, current working directory or remote URL. A `platform` reference remains an explicit reference intended for the **exact** `platformAssetLibraryVersion: "1.0.0"` installed, read-only catalogue. The inventory must preserve namespace as an intrinsic typed discriminator: an identical filename with `entity` and `platform` namespaces is never the same source, and one does not substitute for the other. Nothing may silently upgrade the platform library version, invent a generic role selection, cross to a sibling Entity, copy platform bytes into Entity source, use a hostname as source authority, or treat suppression as a reason to fall back.

**No media attestation is implemented here.** Merely collecting a valid image filename or seeing `.png` is *not* proof of a file's existence, physical confinement, safe media class, MIME/magic match, decoded dimensions, pixel bounds, digest, licensing, catalogue membership or publication eligibility. These gates remain unavailable and must be explicitly **NOT IMPLEMENTED / UNVERIFIED** for this order, not mocked into PASS. The public/nonpublishing metadata of the existing property candidate must not change. The new inventory API must present an explicit, truthful nonpublication indicator (`GRAPHIC_ASSET_INVENTORY_GRANTS_PUBLICATION_AUTHORITY = false`, or an equivalent plainly named constant). Its result never becomes accepted HTML, a CDN URL, metadata, module prop or an activation/snapshot authority.

If the authoring contains an invalid graphic source envelope, wrong namespace, unsupported extension, missing/extra member, wrong exposure, forbidden favicon format, invalid cardinality or duplicate background source, use the **existing validated parser/resolver refusal** and do not produce an inventory. If a structurally impossible typed mismatch reaches the inventory due to future upstream changes, **refuse** with a safe structured existing-family `ASSET_INVALID` or `PROPERTY_INVALID` error instead of dropping an entry or silently proceeding; do not introduce an unregistered public engineering code or print authored source values in errors. Do not invent a new asset type/format to paper over a missing catalogue.
