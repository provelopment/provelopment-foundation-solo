## Approved Scope — SOLO-WO-048 R03

### 1. Architecture and objective

**Implement Option B — bounded-memory processing with protected temporary storage.** Replace the eager whole-set buffering path with one sequential, disk-backed, resource-safe source-stage assembly path. Preserve the accepted authored-content limits and all existing source semantics. Do not introduce a product-wide aggregate byte ceiling, a second in-memory processing mode or a copy reduction presented as a complete resource-safety solution.

**Problem being corrected.** At R01 HEAD, `read_declared_source_set_v1` retains the selected bytes of all representations in `Vec<SetSourceEntryV1>`, and `assemble_declared_source_set_v1` then retains a second preflight-owned byte copy for each. Individual accepted limits permit JSON up to 2 MiB, Markdown up to 1 MiB, up to 500 Pages, 100 representations per Page and 10,000 EFS nodes within a 2 MiB manifest. A manifest of about 550 KiB with 500 Pages and 10 representations per Page (5,000 representations, 5,503 EFS nodes) fits those independent ceilings. Five thousand 2 MiB JSON bodies total ~9.77 GiB of selected bytes; two retained copies total ~19.53 GiB before metadata and allocation overhead. **This is a risk calculation, not an observed crash or an end-to-end accepted stress fixture.** An uncontrolled allocation failure may abort the process instead of producing the required typed refusal. Passing small-set CI does not prove safety at the allowed maximum.

**Acceptance objective.** One legitimate manifest of any size within **existing** fixed limits must be processed without simultaneously retaining every selected body in memory. Preserve whole-set logical semantics: (1) strict single-manifest parse and the already accepted identity/claim checks, (2) physical reservations for **all declared candidates of all representations before any selected body read**, (3) exactly one JSON-first chosen body per representation with the current per-file native guarantee, (4) already accepted selected-body preflight, (5) protected, owned staging of validated bytes, and (6) only on success an **inert, complete, provenance-bearing, immutable-on-access, disk-backed source-stage candidate**. Any failure means one typed refusal and **no observable partial candidate**. The stage remains non-publishing and does not assert a simultaneous source/manifest/filesystem snapshot.

**Unchanged normative limits and boundaries:** Manifest ≤2 MiB; selected JSON body ≤2 MiB; selected Markdown body ≤1 MiB; existing EFS node, Page and representation-count ceilings; one Entity; source locator and hardlink/case/alias refusals; `sourceCandidates` JSON-first (present invalid JSON refuses; absent JSON only when positively proven); unselected Markdown locator and ownership inspected, **unselected body never read or parsed**; no directory scan; private/unlisted and source provenance not exported; source-stage preflight only. `SOURCE_READ_PROVES_GLOBAL_SNAPSHOT = false` and `SOURCE_READ_GRANTS_PUBLICATION_AUTHORITY = false` on all available results. No route, HTTP, rendered Page, schema registry, Markdown/GFM module implementation, asset parser, cryptographic seal, activation, release or deployment.

### 2. Permitted design, non-negotiable security properties

**A. One selected body at a time.** Replace the production-reachable eager whole-set path with a carefully specified sequential visitor/sink or equivalent state machine at the application port boundary. The pure application layer does no filesystem work, never imports an adapter and keeps the existing `SourceReadPort` and per-declaration `read_declared_source_v1` semantics. It first performs the accepted all-candidate reservation pass over the full declaration set, then hands off **one** owned selected body/evidence at a time to the adapter's private staging transaction, releasing that body's transient bytes before proceeding to the next. Its failure route aborts the transaction; callers cannot obtain an incomplete `ReadSourceSetV1` as a successful result. An arbitrary public iterator or callback that exposes a subset as an accepted candidate is **not** an equivalent fix.

The existing public `read_declared_source_set_v1` and exported `ReadSourceSetV1` currently expose an unbounded eager aggregation path. This path must be **removed, rendered non-production-reachable, or replaced with genuinely bounded semantics**; do not merely add a safe second method while leaving a public all-body accumulator available. Any changing Rust API must update its dependent exports and tests **within the frozen ledger** and preserve the externally agreed logical behavior. No unreviewed alternative buffering path may remain.

**B. Bounded live RAM, no total-content rejection threshold.** Keep only one selected body and its transient parse/preflight copy at a time, plus explicitly bounded I/O buffers, the ≤2 MiB parsed manifest and **O(number of declared representations) small metadata** (lineage, selected kind, path, identity, length/fingerprint and stage-handle references). Avoid a `Vec` of all selected bodies, any memory-map of the entire staged collection, and hidden per-representation byte caches. Use checked arithmetic and fallible metadata/container reservations (`try_reserve` or equivalent) where practical. Refuse genuine allocation, handle, storage or resource errors as safe typed outcomes; a bare unchecked `reserve`, `with_capacity` over an unchecked value, panic or termination is not an acceptable capacity policy. A constant or small multiple of the **accepted single-body maximum** is a design budget for in-flight *body bytes*, not a new combined authored-content limit. Prove that the peak retained body-byte memory is independent of the number and cumulative size of representations; account for parser allocations and any runtime overhead separately and truthfully.

**C. Protected, durable-for-lifetime staging without publication.** Require an explicitly supplied and validated staging-root **capability or equivalent scoped ownership**, separate from authored `content/`, assets, drafts, generated output and Git tracked paths. This is temporary internal processing, not a second manifest, source authority or publication artefact. Do not silently choose or overwrite arbitrary OS temp, a user's home, a sibling repository, or a pre-existing Owner directory. Create each task-owned staging namespace with exclusive no-adoption semantics; verify its actual location and confinement. Distinguish the runtime's designated scratch capability from Agent-only `.temp/`/Cline scratch governance. Provisioning/capacity failures must refuse rather than silently switch to an all-RAM fallback.

For **each** validated body, write to a newly owned private staging object under a checked failure path, verify the write/close-or-flush result and exact byte length, and retain an owned guarded reference or handle. The complete candidate must expose **fallible, bounded-memory reads/streams** of staged bytes; there must be no eager `&[u8]` accessor that forces retaining every member's bytes. Preserve member kind, logical locator, qualified five-part lineage, physical source identity, original byte length and the existing FNV linkage fingerprint, but **never use FNV as an integrity/security proof**. The result is immutable in its public contract: no mutating access, and no accepted byte stream can silently change, truncate, redirect, replace or alias after validation. If stable staging across its lifetime cannot be *proved* on a host, refuse; `chmod readonly` or a user-controlled pathname by itself is insufficient security evidence. Confirm safe behavior on Linux and Windows against after-staging writes/truncations/replacements, including held-open writer / mapped-view attempts wherever applicable. Be precise about same-user OS threat boundaries, not a universal theorem.

Prefer the smallest host-proven primitive already available through Rust standard APIs and approved pinned native dependencies. A Linux anonymous/unlinked handle-backed object (for example an appropriate existing `rustix` `O_TMPFILE` route) and a Windows exclusive handle with verified no-write/no-delete sharing and suitable lifetime cleanup are **candidate mechanisms to investigate, not assertions they work or authority for extra features**. A checked, privately owned named-file strategy is acceptable **only if** it proves the same no-replacement/no-write and lifetime requirements on both actual CI hosts, including the pre-existing writable mapping case. All OS-specific I/O stays in the existing **outer adapter** boundary; the single audited Windows-gated `unsafe` boundary remains unique. **No new project-owned `unsafe`, FFI declarations, crates, feature flags, build scripts or lockfile changes are authorized.** If equivalent safe staging cannot be implemented within existing bindings and permitted source paths, STOP with the smallest requested Owner decision rather than weaken security or add an unreviewed native escape hatch.

**D. Transaction, cleanup and recovery.** A staging attempt has a private, invisible incomplete state. A failure at **any** point—parse, reservation, one body read, selected-body preflight, stage creation/write/flush, capacity exhaustion, integrity check or a late member—returns one typed refusal and drops/cleans every task-owned intermediate it created. Do not expose even the successfully staged earlier members on a failed attempt. On success, the candidate **owns** the staging-lifetime guards until it is dropped; reading any member later must not reopen the original authored source or trust a path that can be replaced. On drop, close handles and clean *only* its exclusively created objects; never pre-clean, recursively delete or adopt pre-existing/unknown paths. Handle an interrupted process without leaving recoverable plaintext in a shared user/Owner directory: prefer OS-managed object deletion where supported, or prove a narrow safe scheme and report its limitations. Never remove unfamiliar leftovers at startup. Fail closed on verified inability to allocate scratch space, access private staging securely, or finalize any object.

**E. Typed refusal and diagnostics.** Carry safe declaration index / qualified lineage and the existing registered error semantics without revealing local absolute paths, secrets or private content. Reuse an **accurate** existing `SOURCE_*`, `SNAPSHOT_*` or applicable `PREFLIGHT_*` code; explicitly classify storage exhaustion, staging I/O, post-stage tamper/change, and inability to establish secure staging. Do not mislabel a staging I/O failure as a positively confirmed absent authored JSON, do not turn storage exhaustion into a Markdown fallback, do not invent an unregistered `GENERIC_ERROR`, and do not redefine an approved code merely to get green. If no existing registered family code can accurately represent a failure, STOP for the smallest separately approved diagnostic contract change.

**F. Preservation of existing product and OS boundaries.** Keep the accepted Linux D2 `rustix 1.1.5` anonymous `FICLONE` proof, Btrfs positive and tmpfs negative, unlink/replacement behavior, no-follow containment and hardlink reservations; Windows 2025 `ShareAccess = FILE_SHARE_READ`, live writer exclusion and original-handle-less writable mapping refusal; strict architecture/unsafe checkers and negative failure-detection gates. No change to the original **source-root/native source-reading** operations is permitted as a workaround. If modifying the native module to add a **safe staging-only helper** is genuinely necessary, do not alter `open_leaf`, `read_bounded`, `recheck`, their behaviors or any native feature/unsafe allowance; keep the existing native test suite intact and prove the new helper under actual hosts. The existing four-crate inward graph and Cargo.lock are frozen.

**G. Not a global snapshot.** Sequentially validated and staged immutable copies establish that the completed candidate's **staged bytes** remain stable once acquired. This does not establish that all original authored files, the manifest and assets came from one simultaneous filesystem state. Refuse observed races; do not invent whole-candidate consistency proof, cryptographic digest, atomic activation or publication authority. Full Markdown/GFM, twenty-two module contracts, asset/link validation, route/locale/visibility/property projection and output sealing are later stages and **not** delivered here.

**II — Implement the sequential application protocol.** Reserve all candidate claims first. One source result at a time is passed to a private adapter transaction. Preserve declaration order, all accepted refusal kinds, no early content body read before reservations, no duplicate source claim, no markdown fallback on malformed/unreadable JSON. **III — Implement and adversarially verify staging.** An explicit trusted staging root, exclusive creation, owned handle/object guards, checked writes/flush/length and fallible bounded reads. Retain source/lineage evidence and every R01 logical positive and refusal. Consume/drop the temporary preflight bytes each iteration.
