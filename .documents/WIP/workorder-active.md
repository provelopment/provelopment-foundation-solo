### 3. Mandatory policy behavior, inert body preflight and refusal matrix

**A. Stable, pure policy input and output.** Introduce a **typed** representation of an observation supplied by a future trustworthy source-acquisition adapter, explicitly distinguishing `Absent`, `Present(bytes)` and `Failure(kind)`. A failure kind must be explicit and distinguish at least permission/access, other I/O, unsafe location/identity and changed-during-read; no catch-all conversion to `Absent` or empty bytes. The pure policy does not acquire or attest an observation. Preserve the accepted `SourceCandidateSetV1` (its `.json()`/`.markdown()` and `SourceCandidateKind` APIs) rather than building a second source declaration or bypassing its lexical validation. Avoid a public `Exists` boolean divorced from a byte observation. A successful outcome must be named `Provisional…`/`Selected…Candidate`, **not** `ValidatedBody`, `EffectivePublishedSource`, `PublicationReady` or `VerifiedSnapshot`. The policy may borrow input bytes; it never asserts a verified filesystem snapshot. It has zero I/O and zero dependency and uses no `unsafe`, clock, random, locale, URL or directory state.

**B. Exact precedence and read-order policy.** If a `json` candidate is declared, its explicitly supplied observation is required **first**. `Present(json_bytes)` chooses JSON provisionally **without observing or reading unselected Markdown body bytes**, whether JSON bytes later pass or fail body preflight. If the declared JSON is safely reported `Absent`, and only then, a declared Markdown observation is required; `Present(markdown_bytes)` chooses Markdown. A JSON `Failure(_)` is an immediate typed refusal even when Markdown was declared. If only Markdown was declared, its observation is required; Markdown `Present` chooses Markdown. If all declared candidates are explicitly `Absent`, return `NeitherPresent` refusal, never a fabricated empty Page. A status supplied for an undeclared candidate is refused. A supplied Markdown body observation while JSON is present is refused as an unexpected/unnecessary body-read observation, not consumed or parsed; this does not prohibit a **future** filesystem adapter from proving unselected Markdown *identity/ownership* via metadata without reading its body. Reject missing required observations and any inconsistent kind/path pairing. Read order and winner cannot vary with declaration order or filesystem enumeration. There is never merging of JSON and Markdown, fallback after a JSON `Present`, inferred suffix, directory scan, or a second publication authority.

**C. JSON body-byte preflight (not full schema validation).** In `solo-adapters`, accept **only** the provisional JSON choice's already supplied bytes, with the maximum **2 MiB**, strict UTF-8 **without BOM**, no trailing input, comments, YAML, `NaN`/`Infinity`, invalid JSON or duplicate object keys at **any nesting depth**. Reuse the accepted `DeclaredNode` serde visitor that rejects duplicates at map access, rather than deserialize first to a collapsing map or `serde_json::Value`; do not edit its accepted implementation. Validate the **closed body root** from §6.2E.1: an object with exactly required `contentVersion: "1.0.0"`, required nonempty `title` of at most 140 Unicode scalar values, optional `summary` of at most 500 scalar values, and required `blocks` array with **1–250 elements**. Do not infer a title, version or empty block. The module bodies/props/presentation remain **unvalidated** against the full module registry, active schema and Unicode normalization rules; preflight may retain the ordered syntax tree or merely validate and retain owned bytes. It MUST NOT claim schema-closed module/props validity, safe rendering or publishability. A JSON `Present` whose bytes fail any preflight check is a **refusal**; it must not call Markdown selection after that failure. The output and diagnostics must be named **inert/preflight**, never publication-authorized.

**D. Markdown byte preflight, also inert.** For a provisionally chosen Markdown body, accept only supplied bytes of at most **1 MiB**, strict UTF-8 without BOM, with no byte rewriting or content merging; return an owned inert byte/text candidate. **Do not** claim CommonMark 0.31.2, GFM 0.29-gfm, raw-HTML refusal, H1/heading semantics, anchors, link safety or parsed Markdown validity — none is installed by this order. Empty, malformed UTF-8, BOM or oversized selected bytes must be refused as appropriate. A Markdown preflight success is explicitly not an authorized or validated body; future full content validation must refuse raw HTML and invalid headings before publication.

**E. Owned, stable memory boundary without false filesystem claims.** The adapter's successful preflight result owns an immutable byte copy (e.g. private boxed bytes or equivalent), and no public mutable escape may change that copy. Mutating/reusing the caller's input buffer after the call must not alter the preflight result. This establishes **in-memory ownership only**; it is not a disk snapshot guarantee. Keep associated selected logical locator and kind traceable by typed fields, and expose no physical absolute path or sensitive supplied body text in error `Display`. Source bytes may be large but must be bounded *before* copying; avoid unbounded recursion/stack and do not accept unsupported deep inputs by silently truncating them.

**F. Safe parsing composition and hard trust boundary.** One documented public in-memory pipeline must be testable without private fields: parse the sole manifest's already supplied bytes by accepted `parse_manifest_bytes`, traverse the one Entity/Facet/Site/Page/representation, obtain its already parsed `SourceCandidateSetV1`, provide typed observations, choose provisionally, preflight **only the chosen bytes**, and return an inert result. If a declared JSON is `Present` and invalid, the pipeline refuses even when a valid Markdown byte buffer also exists elsewhere: that buffer must never be requested, selected, inspected or merged in this path. A representation's locale and route remain raw authored declarations; no call converts these unvalidated strings into a production canonical-locale key or public route. An undeclared candidate or file never receives a path through this pipeline. The accepting parse of a manifest, observation or body does not make any of them publication-authorized.

**G. Required positive/adversarial proofs, all via public API.** At minimum test: only JSON/only Markdown; both declared with JSON present; both with genuinely **supplied** JSON absence and Markdown present; JSON absent/Markdown absent; JSON read error with Markdown logically present; JSON present but syntactically malformed (including duplicate root and deeply nested member), no Markdown fallback; unwanted Markdown body observation when JSON is present; an observation supplied for an undeclared candidate; missing required observation; byte-empty vs explicit absent; permission, other I/O, unsafe identity and changing-content failure all distinct; JSON exact 2 MiB boundary and 1 byte over, Markdown exact 1 MiB boundary and 1 byte over; UTF-8/BOM refusal for both; malformed/trailing JSON; non-object JSON root; missing/extra root keys; unsupported `contentVersion`; title and summary scalar bounds; empty/too-many blocks; preservation of selected JSON/Markdown logical path, kind and owned bytes; caller buffer mutation after preflight; safe bounded diagnostics without echoed content/root; parser candidate and preflight candidate both `is_publication_authorized() == false`; no filesystem access anywhere. Tests at size ceilings must not accidentally exceed process memory/time budgets. Existing accepted parser/locator tests and all other workspace tests must pass unchanged. If a necessary test requires editing an unlisted file, STOP rather than widen scope silently.
