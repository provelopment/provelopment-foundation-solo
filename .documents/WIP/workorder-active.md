## 3. Narrow contract and required corrections

### 3A. R03C2-04 — compare **actual bytes** on repeated logical references

The current implementation stores `(PhysicalIdentityV1, u64 length, u64 fingerprint)` in `seen_paths`, and at the second same-path observation compares only identity, length and a 64-bit **noncryptographic** fingerprint. At `graphic_asset_read.rs` around the R01 source lines 619–624 it does not compare the two `Vec<u8>` bodies. Different byte strings with equal length and equal supplied/observed fingerprints can thereby pass as a consistent repeated reference. This violates the issued R03C2-04 same-reference consistency condition.

**Required behavior:** within one whole-inventory acquisition attempt, when exactly the same `assets/…` logical reference is authored multiple times, preserve the multiple independently authored obligations and read **each occurrence**, while requiring the **exact acquired byte sequences** to agree, alongside identity, reported length, link count and existing fingerprint checks. A change in identity is `IdentityCollision`; same identity but differing bytes is `ChangedDuringRead` even if the fingerprint is equal, or even if the fake outbound port supplies matching fingerprints. No current public accessor, type, diagnostic category, 20 MiB bound, original obligation ordering or publication/media flag may change. Evidence remains immutable owned bytes; no cryptographic hash, global multi-file snapshot or media provenance is claimed. Existing distinct-path physical-identity collision behavior remains unchanged.

**Implementation approach:** prefer comparing the second owned `bytes` with the first occurrence's **already retained evidence bytes** (e.g. a path→index lookup into the existing `evidence` vector, or another minimal bounded safe approach); this avoids storing a second full 20 MiB copy solely for comparison. Retain consistency checks of identity, length and fingerprint where relevant, but **fingerprint equality is never a substitute for byte equality**. No deduplication of obligations, no new hash crate, no rendering, no silent reread fallback. A mismatch refuses the **entire** result, discarding earlier partial evidence from the public outcome. The refusing owner/role/index must be the second obligation that detected the inconsistency.

**Mandatory regression:** a real whole-graph/typed inventory with the same `brand/shared.png` authored at two distinct levels and a controlled port giving (i) same identity, same length and **same manually supplied fingerprint** but **different actual bytes** — must be `ChangedDuringRead` and must expose **no** partial success; (ii) exact equal bytes and consistent identity/length/fingerprint — two separately ordered pieces of evidence, two outbound calls, both owner coordinates preserved; (iii) changed physical identity still `IdentityCollision`; (iv) distinct authored paths resolving to one identity still `IdentityCollision`; (v) stable diagnostic contains no raw path or source bytes. Do not rely only on deliberately different hashes. Keep all earlier `r03c2_*` tests runnable and meaningful.
