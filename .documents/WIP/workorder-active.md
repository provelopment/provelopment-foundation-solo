### 4. SourceRead's mandatory security and authoring contract

**Authority.** The reader sees only source candidates that came from the accepted `SourceCandidateSetV1`; caller-chosen paths, directory enumeration, inferred suffixes, undeclared candidate reads, adjacent sibling fallback and source-file metadata authority are forbidden. Its application port is owned inwardly and exposes typed, deterministic statuses; the real adapter never publishes, routes, decides visibility, parses Markdown/JSON, seals or activates. The supported read request identifies an accepted logical locator and an explicitly trusted root capability. A bare `PathBuf`, absolute path or unchecked string cannot silently become a trusted capability. A single use case with a fake and real adapter must exercise the port so it is not decorative.

**Observations.** Distinguish positively demonstrated `Absent` from `Present(owned bytes, physical identity evidence)` and typed `Failure` for permission, I/O, unsafe location/reparse, uncertain identity/collision, race or changed-during-read. Do not convert `PermissionDenied`, failed directory traversal, unsupported API, loop, inaccessible parent, rename race, reparse result or ambiguous Windows error into `Absent`. A reported JSON absence may enable the *existing* JSON-first policy only where the adapter has independently proven safe candidate absence. Missing a declared candidate is not equivalent to an empty, invalid or unreadable file. A selected malformed JSON body never triggers a Markdown read. A chosen winner cannot silently overwrite a previously reserved source ownership claim.

**Confinement.** Resolve only within the correct explicit `content/` capability and `pages/` namespace. All path components obey already accepted lowercase-ASCII logical rules; traversal, absolute/drive/UNC, percent, backslash, alternate data streams, reserved names, short-name aliases, dot segments and other escaped spellings refuse before filesystem traversal. No follow of any symlink/junction/reparse at root, intermediate directory or leaf. Refuse mount/volume boundary escapes and any unprovable root substitution. A race-safe handle-relative traversal and stable handle identity are necessary; path-based `metadata`, `canonicalize`, an initial check followed by an unconstrained open, and a string-prefix comparison are categorically insufficient. Use only OS APIs actually verified on Ubuntu 24.04 and Windows 2025 with the pinned toolchain. `cap-std`'s capability confinement alone must not be represented as no-follow or physical-identity proof.

**Identity, claims and bytes.** Gather physical identity from the *opened handle*, or refuse when unavailable. On Linux show robust device/inode/hardlink detection; on Windows demonstrate volume plus file-index/ID and reparse/alias controls on the actual handle, not on a separately followed name. Do not treat case-fold string comparison as sufficient physical identity. At minimum, refuse two separately declared logical candidate names that resolve to one physical file, even across distinct representations; enforce that every declared candidate's ownership is checked without reading an unselected Markdown body. Do not claim physical collision proof for an **absent** path unless its namespace/alias reservations are genuinely established; use the already accepted logical reservation as the first layer. Do not silently share a file via hardlinks.

**Immutable copied evidence.** Bound each source before and during read using 2 MiB for JSON or 1 MiB for Markdown (read at most limit + 1 for overrun); forbid unbounded alloc, integer overflow, partial-body success, invalid file type and directory reads. Hold a private owned immutable byte buffer and a safe fixed-length physical identity/digest/provenance record; preserve the opened handle through read and resample metadata/content as necessary. Detect and refuse changed identity/size/content/race (`SNAPSHOT_CHANGED`), and **never** assert a globally consistent filesystem snapshot where a concurrent writer can still create an undetectable torn read. A previously copied immutable in-memory byte slice is not alone such proof. Document precisely what the chosen API demonstrably guarantees and what remains unproven; unresolved adversarial races must STOP rather than be waived.

**Diagnostics.** Stable, safe codes consistent with Architecture §6.2K (`SOURCE_UNSAFE_PATH`, `SOURCE_COLLISION`, `SOURCE_NONE_EFFECTIVE`, `SOURCE_INVALID`, `SNAPSHOT_CHANGED` where applicable). Diagnostic Display never exposes private absolute paths, authored body bytes, secrets, OS handle values or process environment. Fixed bounded messages with safe logical identifiers only. No `unwrap` on untrusted data, panic recovery as success, unsupported-platform fallback or hidden `unsafe`.
