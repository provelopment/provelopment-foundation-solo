### 2. Selected stack, delivery neutrality and compatibility qualifications — `E01` / Owner condition C2

**Architectural shape:** Rust 2024 is the publication/domain language. The product has a **publish-time validated, content-addressed artifact pipeline** and a **request-time transport-neutral response resolver**; optional HTTP adapters can run in a long-lived Axum process, a platform-specific on-demand function, or a compatible request-aware gateway. Do **not** make a permanently running Rust process, Node runtime, database, hosting provider, CMS, or background watcher a prerequisite of the *published content artifact*. ### 6. Confinement, bounded media, provider-neutral sealed publication and activation — `E06` / Owner condition C2

**Source boundary:** O03 paths remain portable lower-ASCII relative locators, ≤240 bytes and ≤8 segments, leaf/source extensions governed precisely by the Charter; reject absolute/UNC/traversal/dot/backslash/percent/reserved Windows stem, case/short-name/Unicode alias, symlink/junction/reparse, mount escapes, hardlink identity sharing and unprovable race. Separate Installation `content/pages`, `content/assets`, nonpublished `content/drafts`, product-distributed `platform/assets` and `contracts`. Only the manifest claims publication; a genuinely absent JSON candidate can select *declared* Markdown; inaccessible/corrupt JSON is an error, not absence. `SourceRead` operates through handle-relative confinement (`cap-std=4.0.3` plus OS-specific verified descriptor/reparse/file ID/links logic). Linux `openat`/safe no-follow restrictions and Windows handle/reparse/volume/alias checks must be actually exercised on their platforms; unsupported safety guarantees fail closed. Hold immutable copied bytes and metadata/hash per candidate, resample where required, detect change and reject `SNAPSHOT_CHANGED`; no string-prefix safety fiction.

**Asset pipeline:** typed entity/platform asset refs only; initial PNG/JPEG/WebP/AVIF bounded 20 MiB, 8192px max side, 32M pixels; MP4 AVC/optional AAC-LC or WebM VP9/optional Opus 200 MiB, 180s; WebVTT 500 KiB with safe parser; no SVG, GIF, external URL, unapproved embeds/codec or inferred generic artwork. Verify MIME/magic/codec/decoded structure in sandboxed bounded offline inspectors, decompression/panic/timeout denial triggers whole-publication refusal. Use native AVIF/FFmpeg only after platform build and license/notice proof. Derived immutable assets are outputs, never authored sources or undeclared fallback. Generic role fallback is **zero** per accepted O09. The published artifact includes exact content hash, mime, content length, provenance and public-eligible exposure for every derived asset.

**Single portable sealed artifact:** `SealPublication` consumes **one fully validated immutable candidate** including every published representation (public and unlisted) and emits a read-only *content-addressed directory/object set* with: (a) manifest schema/registry/product compatibility tuple and normalized safe base; (b) complete route/locale/visibility/alias/entry claim ledger (not another authoring manifest); (c) pre-rendered public HTML/response metadata for each authorized representation, including exact unlisted `noindex,nofollow` response and hashed browser assets; (d) immutable typed media outputs and hashes; (e) public-only discovery data derived from authorized public representations; (f) object digests, total artifact digest and public exposure boundary. Internal source/private values and provenance are **not** exported into any publicly retrievable file. Generated metadata has no publication authority; the installation's `content/publication.json` remains sole source authority. In-memory validated models that include internal facts stay private during seal generation and are never mixed with published bytes.

**Publication and activation protocol (portable contract, no provider presumed):** `ArtifactWriter` writes to staging namespace not live/public, fsync/verify as supported, re-reads all sizes/digests, produces a **sealed immutable snapshot ID**. `ActiveSnapshot.compare_and_swap(expected_id,new_id)` is the sole activation operation: after all checks pass, change a **single atomic pointer**; on mismatch/error leave old ID intact. The identity is the hash of a canonical versioned seal index over sorted paths/digests/contract tuple and base, not mtime or directory listing order. Request/resolution reads a pinned active snapshot ID at entry; all page, asset, redirect, canonical, cookie and cache decisions for that response use that same ID; no mutable content source access or unvalidated fallback. Reject if expected artifact missing/corrupt or if activation cannot be atomic in that host. Revalidation and staged replacement never destroy the last valid seal. Content-addressed URLs and cache identities prevent cross-revision collisions; shared caching of preference-selected redirects forbidden.

**Three concrete interchangeable activation adapters, with capability criteria:** (1) local filesystem adapter for preview/local use—same-filesystem staging and rename of a *pointer file* plus `fsync`/directory durability where demonstrable; no claim of atomic directory swap on all OSes; if stable durability unavailable, label only process-local preview/nonproduction. (2) object-store/CDN adapter **as a future provider-specific implementation only**—write immutable objects then conditional strong-ETag or equivalent linearizable pointer compare-and-swap/read; if eventual consistency/partial visibility prevents pinning, refuse compliant activation. R00.G decides retention, recovery, provider, SLA, deployment and durable persistence policy; R00.E fixes interfaces, invariants and refusal conditions, not provider accounts.

**Delivery modes and limits:** Mode A, **static exact-route artifact serving**, may directly serve verified pre-rendered canonicals/assets without a Solo server *only where the real hosting configuration enforces all authored route, alias, canonical, cache, 404 and exact-case unlisted outcomes*. Mode B, **request-aware resolver**, is required for otherwise unsupported dynamic route/case/locale negotiation behavior. A provider that cannot safely support the required route semantics cannot honestly claim complete Solo conformance for that Installation; fail rather than simulate. Later R00.F contact form requires an approved replaceable submission endpoint; no serverless vendor or paid service is preselected. R00.G decides the supported deployment modes and recovery commitments.
