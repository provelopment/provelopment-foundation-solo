## 5. Native design and bounded probe contract

**5A. One safe façade.** Name its fixed public entry point `run_linux_media_host_probe_v1`, accepting only a strongly typed `MediaHostProbeModeV1` and `MediaHostLimitsV1`, plus a **trusted absolute path identifying the current `solo-cli` executable** supplied by the controlled test/composition root; never expose an arbitrary executable/argument runner or accept an authored path, URL or shell fragment. The safe façade validates the exact fixed modes/limits and returns one typed `MediaHostProbeOutcomeV1` (`Observed` only on verified normal completion; otherwise `Refused(MediaHostRefusalKindV1)`). Provide stable refusal codes for unsupported host, untrusted/missing executable, invalid mode, invalid limits, launch failure, limits unverified, abnormal child exit, CPU limit, memory limit, wall timeout, descendants remaining, invalid/bounded evidence, and cleanup failure. Never return raw child output, absolute path, OS command text, secrets, panic content or unbounded diagnostics as a public refusal. A typed `Observed` report is a smoke observation, **never** media verification or publication. Limit evidence to a small, fixed protocol (≤4 KiB); refuse overflow, malformed values, altered readback or trailing input. No new app/domain port and no `MediaWorkerPortV1` implementation in this order.

**5B. Limit and time values.** Normal profile: `RLIMIT_AS` soft=hard=**536,870,912 bytes**; `RLIMIT_CPU` soft=hard=**10 seconds**; parent wall deadline **15,000 ms**. Probe-only profiles: 64 MiB AS and 10 s CPU for 128 MiB touched-allocation; 512 MiB AS and 2 s CPU for finite 20-second spin; 512 MiB AS/10 s CPU and 2,000 ms parent wall deadline for 20-second sleep/descendant probe. All values installed in the child **before `exec`** and never weakened automatically. Linux `RLIMIT_AS` bounds a *single process's virtual address space*, not RSS or aggregate descendants; `RLIMIT_CPU` limits consumed CPU time, not exact elapsed time. Watchdog and cleanup completion are measured and reported. Unknown Linux kernels, missing primitives, unsupported architecture or denied limits must produce typed refusal, never an unbounded fallback. For this order, the enforced scope is Linux x86_64 `ubuntu-24.04`; other Linux kernels/platforms are not certified by this evidence.

**5C. Linux mechanism (native module only).** Use `std::process::Command` in the safe façade and the Linux `pre_exec` hook in the platform-gated native module; use existing pinned `libc =0.2.191` for `setsid`, `setrlimit(RLIMIT_AS/RLIMIT_CPU)`, `kill`/signal and any narrowly required native wait/status checks. Every actual unsafe occurrence must lie within a **positive** `#[cfg(target_os = "linux")]` module/item and have an adjacent exact `// SAFETY:` invariant. `pre_exec` runs in forked child context: do **only** async-signal-safe native operations there; no allocation, `format!`, panic, logging, mutex, filesystem reads, Rust heap work or nontrivial closure capture. On any error, return the minimal predeclared OS error/refuse without executing the worker. Spawn into a new session/process group, preserve a trusted executable identity, close unintended inherited handles, disable shell/PATH resolution and stderr forwarding, and bound stdout/evidence read. Read back actual limits from the child itself (e.g. `/proc/self/limits`) **before** stress or control-mode work, and assert the exact values. Avoid inherited environment secrets: pass only a fixed allowlisted environment required to launch the already-built trusted binary, not `env::vars()`; no file source reads, no network, no external process helper. If static linking/loader constraints prevent that on the runner, STOP rather than silently relaxing the control.

**5D. Watchdog, descendants, output and lifecycle.** Parent measures monotonic elapsed time, terminates the **entire** private process group on timeout/abnormal/error, escalates safely from TERM to KILL, reaps the direct child and verifies group extinction or refuses. Ensure no child survives every terminal path, including a panicking test cleanup path. A child worker may deliberately create one fixed descendant solely inside the controlled Linux smoke test; it cannot select arbitrary executables or paths. A plain process group does not prevent a malicious child from creating another session: record this gap explicitly; no security-sandbox or aggregate-process-memory claim. No stdout/stderr or staged file is promoted on any abnormal outcome. Handle EOF/partial/overlarge output, I/O errors and missing readback as typed refusals, with bounded buffers and no deadlock if the child writes an unlimited stream. `Observed` requires verified normal exit, matching limits, within wall time, no remaining descendants, correct fixed evidence and completed cleanup. No assumptions from exit status or a child's own `true` flag alone.

**5E. Internal CLI probe.** Add one exact literal `--internal-media-host-probe-v1` with a fixed mode token and fixed numeric parameters; never expose a generic command executor. Modes: `readback-control`, `allocate-128m`, `spin-20s`, `sleep-20s`, `spawn-descendant`, `descendant-hold`. The internal child checks its **own effective resource limits before performing any potentially expensive workload**; if limits are missing, unknown or inconsistent, terminate immediately with a fixed refusal and **zero stress**. This self-check is a defense-in-depth negative control, not cryptographic proof the parent launched it or installed a wall watchdog. `spawn-descendant` must use the same verified executable and only the fixed `descendant-hold` mode; no arbitrary command args or external tool. On Windows, this internal mode refuses immediately as unsupported before any work. Normal external CLI functionality remains byte-exact and unchanged. No panic/unbounded operation when arguments malformed; direct unsupervised invocation under the normal host environment must refuse before touching 128 MiB, spinning, sleeping or spawning (strict short-timeout test).
