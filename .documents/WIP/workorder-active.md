## A01 / O01 — Files, schema identities, encoding and resource limits

1. Installation-authored authoritative manifest: **`content/publication.json`** (exact slash-separated relative location under the Installation root). Exactly one file at this address is admitted as publication authority. No second manifest or directory-discovery path, including through links or aliasing.
2. Manifest root field **`schemaVersion`: `"1.0.0"`** is mandatory and exactly matched to the supported first contract. Manifest JSON is UTF-8 without BOM, RFC 8259 strict (duplicate keys, NaN/Infinity, invalid UTF-8 and non-JSON syntax refused), unknown fields refused. Root must be a nonnull object; maximum 2 MiB; no parser-recovery, duplicate-key overwrite or YAML. Manifest UTF-8 normalizing is not implicit: authored ID/path/locale strings are validated by their own rules.
3. First JSON Page body format: UTF-8 strict JSON, mandatory root `contentVersion: "1.0.0"`, maximum 2 MiB per selected source, unknown fields refused, no execution. Markdown: UTF-8 without BOM, maximum 1 MiB. Author-written data and delivered assets follow different roots and cannot override one another.
4. Namespace roots relative to the verified Installation or product package: `content/pages/` for Page candidate bodies; `content/assets/` for Entity-owned assets; `content/drafts/` for drafts never scanned/published; **product-distributed, read-only** `platform/assets/` for shared generic public assets; product-distributed `contracts/` for validated schemas/module registries, not publication manifests. Generated immutable outputs live in a separate output namespace that is never an input root. Secrets and server-only configuration live outside these source roots.
5. Manifest candidate locator strings are **relative to `content/`**, must begin `pages/` and point to the selected extension. E.g. `pages/main-home.en-001.md` resolves to `content/pages/main-home.en-001.md`; a candidate cannot reference the manifest itself. Entity asset `reference` strings are relative to `content/assets/`; platform asset `reference` strings are relative to product `platform/assets/`. Physical mapping never guesses suffixes or scans directories.
6. Future first implementation artifacts: `contracts/publication/1.0.0.schema.json`, `contracts/content/1.0.0.schema.json`, `contracts/properties/1.0.0.schema.json` and one registration/schema per named module under `contracts/modules/<module-id>/1.0.0.schema.json`. These are **future code-stage paths**, not files to create in this order. JSON Schema dialect is **Draft 2020-12**; conforming validators must enforce `unevaluatedProperties: false` (or equivalently complete closed evaluated object shape) and asserted formats via explicit domain checks or format-assertion support. A schema keyword silently treated only as an annotation does not satisfy a security assertion.
7. All schema-version strings use **three decimal numeric components `MAJOR.MINOR.PATCH`** without prefixes, leading zeroes or range expressions in authored values; independent manifest, content, registry, module and product versions. Contract `1.0.0` is the first exact supported baseline, not a promise of installed software. The exact contract files are specified here; their code-generation, validator dependency and build tool are R00.E/Stage 02 implementation work.

Resource exhaustion limits for contract validation: maximum 10,000 EFS nodes including representations, 500 Pages, 100 representations per Page; maximum 250 module nodes per JSON body, module nesting depth 12, and 100 entries per property across an effective direct-ancestry result unless a narrower registered bound applies. Publish refusal uses exact constrained field/path diagnostics; no partial publication, automatic source rewrite or lossy truncation.

## A02 / O02 — Exact manifest grammar, EFS identity, publication and source declarations

The root object has exactly these **five required keys**: `schemaVersion` (string), `propertyRegistryVersion` (string), `platformAssetLibraryVersion` (string), `base` (object), `entity` (object). No other root keys. `base` has `canonical` (required absolute HTTPS URL or, solely for explicitly approved local development, HTTP loopback), `aliases` (optional array, default `[]`, distinct canonical URL bases), and `landing` (optional qualified Page reference; omission means base entry returns not-found). The preferred production base uses HTTPS; canonical/alias URL processing is defined in O10.

`entity` has required `id` (technical ID), required `label` (nonempty plain display string), required `facets` (nonempty array) and optional `properties` (governed D08). A Facet has required `id`, `label`, `sites` (nonempty array) and optional `properties`. A Site has required `id`, `label`, `defaultLocale` (full region-qualified tag), required `pages` (nonempty array), optional `languagePreferences` (object mapping accepted request preference strings to authored full locales), and optional `properties`. A Page has required `id`, `label`, `representations` (nonempty array), optional `visibilityDefault` (`public|unlisted`, default public), optional `entryPaths` (array of authored locale-less paths, default empty), optional `missingTranslation` (policy object), optional `properties`. A representation has required `locale`, required `route` (route object), required `sourceCandidates` (object), optional `visibility` (`public|unlisted`), optional `properties`. Direct node containment is parentage; a `parentId`, ancestor pointer, type-discriminator or secondary linked graph is not allowed.

`id` follows accepted regex `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`, 1–63 ASCII characters. `label` is plain Unicode text 1–120 Unicode scalar values after NFC normalization; labels do not create identity, URL routes, locale or location. Facet IDs unique in Entity, Site IDs unique within their Facet, Page IDs unique within their Site; exactly one Entity. Representation locales unique per Page after canonical BCP47 normalization. Each child must have one containing parent. Qualified Page target (`landing` or typed link target) is an **object** `{ "entity": "<id>", "facet": "<id>", "site": "<id>", "page": "<id>" }`, all four fields required; no shorthand. Entity ID must equal the root `entity.id`, and the full parent lineage must resolve exactly. Qualified representation target extends that object with required `locale` when used; no bare Page-ID or guessed Site selection.

`sourceCandidates` object has **one or both** optional members `json` and `markdown`, **string locators**, never null, never an empty object; no additional keys. `json` must terminate `.json`, `markdown` must terminate `.md`, each points beneath `pages/`. JSON-present wins even if Markdown is valid; only genuine JSON absence selects declared Markdown. Any existent invalid JSON rejects; unselected Markdown contents are not parsed, but both locator declarations and uniqueness claims are validated. Neither candidate existing rejects. Same canonical candidate among distinct representations rejects, including absent paths; case-folded/alias/hardlink collisions refuse. Candidate selection does not move EFS identity, routes or properties and never confers publication to unlisted/drafts. The manifest cannot designate a generated or remote source.

`missingTranslation` has `{ "mode": "default" }` (default if field absent), `{ "mode": "strict" }`, or `{ "mode": "locale", "fallbackLocale": "<full locale>" }`. In `default`, Site default representation of the **same Page** must exist and be public for a fallback to succeed; otherwise missing request is not-found and an authored invalid forced fallback is refused. In `locale`, fallbackLocale must be an existing public representation of the **same Page**, validated at publish time. In `strict`, missing is not-found. Actual present public representation always wins; missing or unlisted never silently swaps for another Page or Site. Preference-dependent entry and fallback redirect statuses are defined in O10.

The representation's `route` object has required `path` (full locale-qualified canonical path relative to the configured base), optional `caseMatching` (`insensitive|sensitive` for public; omit on unlisted where exact-case is mandatory), optional `aliases` (array of `{ "path": "...", "caseMatching": "insensitive|sensitive" }`, empty by default). Root/paths/aliases/entries and matching are detailed in O10. `entryPaths` consists of authored locale-less public route strings; it may be empty even if a Page is Home. For effective unlisted representation, authored route aliases are disallowed by first profile (the exact canonical route remains directly reachable); public entries can never expose it.

All object keys not enumerated or expressly registered for the corresponding property/module `props` are rejected, including `draft`, file-level `visibility`, source `locale`, meta-overrides and unregistered section types. Exact array order is authored but never a collision-resolution priority; all acceptance/refusal decisions are deterministic and independent of directory order.

## A03 / O03 — Portable sources, asset paths, snapshots and collision safety

1. A locator/reference is a **single unescaped logical path string**, not a URL: relative slash-separated segments, no leading/trailing slash, no consecutive slashes, no backslash, no `.`/`..` segments, no colon, tilde-expansion, query/fragment, percent escapes, NUL, controls, separators encoded as data, or absolute/drive/UNC paths. Source components are **lowercase portable ASCII** `[a-z][a-z0-9._-]*`, length 1–80 bytes, no trailing dot or space, no consecutive dots, with at least one letter; full reference length ≤240 bytes and depth ≤8. `.json`, `.md`, image and video extensions are lowercase, exact and include a dot. Unicode is supported in **public routes and displayed content**, not in source filenames for the first portable profile.
2. Reject Windows reserved basename/stem forms (`con`, `prn`, `aux`, `nul`, `com1`–`com9`, `lpt1`–`lpt9`) even with extensions, and reject platform-specific aliases/case-insensitive equivalences. A logical path can claim only one canonical resource. Never normalize an invalid path into validity.
3. Source adapter must use an atomic, no-follow, directory-confined traversal under the correct root. Reject symlinks/junctions/reparse points along all path components and at the leaf, mount/root escapes, directory aliasing, unintended hardlink identity-sharing and filesystem race/TOCTOU uncertainty. When an adapter cannot prove containment or canonical ownership, it refuses; **string-prefix tests do not prove containment**. Source validation operates on a consistent snapshot (immutable byte copies/file-descriptor-backed reads plus verified metadata/content hash) before publication activation; a changed source during validation invalidates that candidate snapshot and requires a new full attempt.
4. Canonical candidate claims are compared by root namespace, exact portable path and any underlying filesystem identity/alias/case-equivalence; two distinct published representations cannot reserve the same file whether present or absent. Absence is a first-class, safely confirmed result, not a catch-all for permission or I/O errors. Do not parse or validate unselected Markdown body contents when valid JSON is effective, but do validate its declared locator and ownership even if absent.
5. Entity and platform namespaces never overlap. Graphic/media `reference` includes a **full relative filename with extension**, and resolves without globbing, inferred suffixes, MIME-only substitution or remote fetching. All authoring/discovery output is generated from declared, validated references and routes; generated outputs are never read back as original sources.

## A04 / O04 — Versioned Markdown, HTML policy, headings, anchors and author-friendly links

Markdown profile: **CommonMark 0.31.2** core plus the GitHub Flavored Markdown **0.29-gfm** extension grammar for tables, strikethrough, autolinks, task list markers and disallowed-raw-HTML filtering as described below. Pinned profile means behavior cannot drift with whatever parser the implementation happens to install. No footnotes, math, diagrams, directives, MDX, Solo-specific block syntax or front-matter publication controls in first profile. Standard Markdown blockquotes, lists, code fences, headings, emphasis, links and images remain fully supported.
2. **Raw HTML is rejected as content**, not interpreted and not silently passed through or sanitized into active markup: a parser-recognized raw HTML block or inline raw HTML node is an authoring diagnostic that blocks publication. Literal HTML examples must be placed in fenced/inline code to render as escaped text. Disable HTML output from parsers; escape plain text in the final renderer. No executable code in fenced code blocks. Task-list checkboxes are **read-only**, accessible presentation, not form controls with submissions or state persistence.
3. Standalone Markdown must contain exactly one nonempty H1 heading providing the *body display title*, and it must be the first nonblank semantic block (comments are raw HTML and therefore invalid). H2–H6 are permitted afterward, with no heading-level jump greater than one; a second H1 refuses. JSON content uses exactly one mandatory root display title and may use H2–H6 modules underneath; no duplicate visible H1 may be minted by a renderer. This title is content display text, not EFS identity or canonical URL authority. Plain summary and SEO properties, if supplied, are governed separately; no front matter may override them.
4. Heading anchors derive solely from visible heading text: NFC normalize, lowercase with the pinned Unicode profile O10, retain Unicode letters/numbers plus hyphens, convert every whitespace run to one `-`, strip other punctuation, trim hyphens; if empty, `section`; repeated slugs receive suffix `-2`, `-3`, etc by document order. A `#fragment` target must equal one generated real anchor; empty or missing targets refuse. Any generated renderer ID must be safe and unique; unlisted fragment links do not create discovery inventory.
5. Ordinary `[text](reference)` resolves per RFC 3986 URI-relative rules against the **current canonical Page URL**, not against disk source paths. A leading `/` is origin-root relative and must resolve within the configured approved base prefix; a plain relative reference follows standard URL resolution and then passes the D07 ledger and target visibility classification. Internal targets must be an authorized published route (an explicit safe link to a known unlisted route is permitted but never auto-generated); unknown/ambiguous/internal out-of-base targets refuse. Fragment-only references are same-Page. No automatic locale switching or guessed same-Site slug. URLs inside code spans remain inert.
6. Ordinary `![meaningful alt](images/example.webp)` refers **only** to an Entity asset at `content/assets/images/example.webp`, regardless of the `.md` source directory; the author-friendly Markdown image base is **`content/assets/`**. An image reference is a safe slash-separated portable path without leading `/`, `..` or scheme; it is validated as a typed Entity asset with known MIME and use rights. If a decorative image is explicitly marked with empty alt, the renderer must mark it decorative; otherwise alt text is required. Server-side remote image fetching is forbidden; a Markdown external HTTP image is refused.
7. External links: only safe absolute `https://`, `http://` and `mailto:` schemes are accepted as click-through navigation/action, never server fetch. Reject userinfo credentials, protocol-relative `//`, `javascript:`, `data:`, `file:`, `blob:`, `vbscript:` and unsafe/malformed control/percent encoding. `mailto:` permits one validated addr-spec recipient, optional governed `subject` parameter only, no CR/LF injection, secrets or auto-send; send result is not claimed. `tel:` and custom schemes are not approved in this profile. External `target=_blank` if used requires `rel=noopener noreferrer`; nothing implies an external destination is trusted.
8. Markdown diagnostics include a safe EFS lineage, source locator and line/column for actual selected content, with no raw server-private root, secret, or untrusted HTML reflected in an error page.

## A05 / O05 — Exact advanced JSON body grammar, module envelopes and first installed module catalogue

### A05.1 Body and node grammar

Selected JSON body root has exactly: mandatory `contentVersion: "1.0.0"`, mandatory nonempty plain-string `title` (1–140 Unicode scalar values), optional plain-string `summary` (≤500 scalar values), mandatory `blocks` array of **1–250** nodes. The one visible H1 comes from `title`: if the first block is `content.hero` the renderer places that root H1 within the hero; otherwise it places it before the first block, exactly once. A hero never declares a second H1. The `summary` is body copy and never changes manifest-owned metadata, routing, publication, locale or visibility. All authored text is inert escaped data, with no interpolation, HTML execution, JS/CSS injection, remote includes or template evaluation. Node count includes nodes nested in tabs, accordion and modal items.

Each node is a closed object with mandatory `module` (registered dotted lowercase ID), mandatory `contractVersion` (exact version string), mandatory `props` (closed typed object), optional `children` (**only** for a registry type that explicitly permits child nodes), optional `presentation` (controlled appearance envelope), and optional `span` (**only** as a child of `layout.grid` or `layout.bento`). `children` is always an ordered array of registered nodes and is forbidden for leaf modules. Maximum node depth 12, nodes 250 total, max child-array length 24; a node may not refer cyclically to itself. Never infer a missing module from a filename or component name. Unknown node fields, unknown props, unknown module version, forbidden children or version mismatches refuse publication of the **whole** proposed graph.

`presentation` is a closed optional object: `foreground` optional `#RRGGBB` or `#RRGGBBAA`, `background` optional typed fill, `padding` optional `none|xs|sm|md|lg|xl`, `radius` optional `none|sm|md|lg`, `textAlign` optional `start|center|end`. No arbitrary CSS property, selector, `url(...)`, classname, expression or inherited unvalidated script. Fill is exactly one of `{ "kind":"solid", "color":"#RRGGBB" }`, `{ "kind":"linearGradient", "angle":0..360, "stops":[{ "color":"#RRGGBB", "position":0..100 },...] }` with 2–5 strictly increasing ordered stops starting at 0 and ending at 100, or `{ "kind":"image", "asset":<typed asset>, "overlay":"#RRGGBBAA" }` (overlay optional). The renderer must enforce meaningful contrast and overlay/focus visibility and may **refuse** unsafe contrast combinations rather than silently change colors. Token distances in CSS pixels: none=0, xs=4, sm=8, md=16, lg=24, xl=40. Radius values: none=0, sm=4, md=10, lg=20. Values remain semantic inputs, not author-supplied CSS.

`span` is a closed `{ "columns": { "base":1..4, "md":1..4, "lg":1..4 }, "rows":1..3 }`; at each breakpoint its requested column span must be ≤ its containing grid/bento’s column count, and it may not introduce unbounded overlap. The absent `span` defaults to one column and one row at each breakpoint. Responsive columns is a closed `{ "base":1..4, "md":1..4, "lg":1..4 }`, with `base <= md <= lg`; responsive thresholds for this physical contract: md ≥768 CSS px, lg ≥1200 CSS px, below md uses base. No author-supplied CSS media query.

Module `props` are independently schema-closed and bounded. Required fields are identified with **R**; all unmentioned fields rejected. Text means inert string (1–500 scalar values unless a narrower bound states otherwise), nonempty when required. `asset` always means typed A09 reference; `link` always means classified A10 link. Arrays have authored ordering, no automatic source lookup.

### A05.3 Accessibility and performance refusal boundaries

Visible H1 exactly once, meaningful heading order, keyboard operability, visible focus, declared alternative text and captions, reduced-motion preference, explicit user control for animated modules, accessible tab/accordion/modal semantics, no essential content hidden only behind a hover, no auto-playing audio/video and no off-screen focus traps. Contrast must meet the project-approved applicable accessibility target when specified under R00.G; until then the renderer must refuse known unsafe presentation rather than claim a numeric WCAG threshold was already adopted. The eventual module implementation requires proportional per-module browser/keyboard/assistive-tech tests and layout-shift/resource tests; this documentation order produces only specifications, not claims of passing them.

## A06 / O06 — Module trust, installation, contract pinning and upgrade behavior

1. Only **product-distributed, explicitly registered Solo modules** are eligible. The module registry is a read-only product component whose built-in module IDs and versions are declared in the published product contract; it **does not** publish Pages. No remote npm-style URL, package path, runtime eval/import, authored source code, network-fetched module or user-authored JS module declaration is accepted. Custom modules require a separate Owner-reviewed code-bearing extension policy, not an implicit `custom` field.
2. Module IDs are lowercase dotted technical names matching `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*(?:\.[a-z][a-z0-9]*(?:-[a-z0-9]+)*)+$`, maximum 80 ASCII characters. Contract versions are exact three-component strings per O01; module nodes must name an **installed compatible exact contract version**. No wildcards, `latest`, semver ranges, silent major upgrades or guessing the nearest version in authored JSON. Installed product may support multiple exact module contract versions concurrently, with version-specific validators and adapters; if required version unavailable, publication fails.
3. Each registry entry binds ID + exact contract version to its **closed props schema**, default values, child/nesting rules, `presentation`/media capabilities, required application ports, public projection and accessibility/security contract. Default values only those expressly listed in O05; otherwise missing required prop refuses. A module registry does not get to alter EFS identities, routes, property inheritance, source choice or visibility.
4. A product update may add optional modules or a new compatible contract without changing published behavior of an installation that does not select them. A compatible minor/patch release is not authorized to reinterpret existing serialized inputs, default values or security posture. Incompatible input/behavior changes require a **new major** contract, preserved old decoder where supported, and explicit Owner-reviewed migration; the manifest and every affected content file are revalidated before activation. Removed required contracts cause refusal rather than substitution.
5. Application dependency rule: domain core and application use cases define EFS/validation policies, public projection and named ports; read-only source adapters, asset adapters, module renderer adapters and request adapters implement those ports, composed at a single root. Modules receive only validated, public-projected props; they cannot access filesystem/network/secret stores by escaping the module port. A module needing a newly privileged external integration cannot ship solely by adding a JSON ID; it needs its own approved product/port/security contract.
6. Exact first built-in `1.0.0` ID and version catalogue is O05, and manifest/content/registry compatibility is O11. Product release may implement this catalogue incrementally in later authorized implementation packages, but **cannot claim a complete R00.D-conformant public JSON authoring implementation while any mandatory declared module lacks its contract or fails the accepted tests**. A future deliberately smaller product release needs a newly Owner-accepted supported-capabilities profile, not silent omission.

## A07 / O07 — Governed property catalogue, envelopes, exposure and provenance

1. Manifest root requires `propertyRegistryVersion: "1.0.0"` (independent version from `schemaVersion`); installed product must register that exact contract. Every Entity, Facet, Site, Page and representation may have an optional direct `properties` object; property names are exact registered dotted or plain keys and unknown keys reject the whole publication.
2. Each property declaration is a **closed** `{ "inheritance": "inherit"|"suppress", "currentContext": "none" | [ <typed values/operations> ] }`; both fields required whenever a property is declared. Array length must be ≥1; use literal string `"none"` for no local contribution (an empty array and null are invalid). Absence of the entire property key implicitly inherits. `inherit` takes prior effective values in stable inherited-first/local-next order, `suppress` drops inherited values but **may** add local. Domain validation applies the registry's effective max and uniqueness after resolution. No nearest-value-wins, silent de-duplication, merge or post-filter fallback.
3. Exactly two initial exposure values: `public` and `internal`. Every **new independently authored** property value/fact has an explicit `exposure` property. A registry entry has maximum allowed exposure (`public` or `internal`) and permitted EFS levels; data cannot elevate from `internal` to `public` via inheritance, extension, module, renderer, alias or omission. `internal` describes **runtime output projection**, not secrecy of public source files. No per-field public visibility exception exists for location in this profile.
4. Initial built-in property catalogue, exact keys, types and effective cardinalities:

| Key | New local entry value | Effective cardinality | Allowed levels / notes |
| --- | --- | --- | --- |
| `location` | A08 typed `add` or `extend` operation envelope | 0–16 distinct effective location facts | All five; `extend` updates identified inherited value in place, not a new 17th fact. |
| `graphic.logo` | `{ "source": <A09 image asset>, "exposure":"public"|"internal" }` | 0–1 | All five; if inherited+local both select, refuse unless suppress. |
| `graphic.favicon` | Same envelope; A09 favicon permitted format | 0–1 | All five; favicon may not be an unverified remote image. |
| `graphic.banner` | Same envelope | 0–1 | All five. |
| `graphic.background` | Same envelope | 0–4 | All five; inherited-first layered order. |
| `graphic.social-preview` | Same envelope | 0–1 | All five; safe public metadata projection only. |
| `seo.title` | `{ "text": <plain text 1–140>, "exposure":"public"|"internal" }` | 0–1 | Site, Page, representation only. |
| `seo.description` | `{ "text": <plain text 1–300>, "exposure":"public"|"internal" }` | 0–1 | Site, Page, representation only. |
| `contact.email` | `{ "address": <valid mailbox>, "exposure":"public"|"internal" }` | 0–1 | All five; no implied contact submission endpoint. |

All other property names remain unregistered in the first release. This minimal catalogue is extensible through explicit versioned registry approval, not a new implicit manifest publisher. Registered `exposure` maximum controls which projection may contain a value. For the above types, `public` is permitted; `internal` remains suppressed from all publicly rendered HTML/JSON/metadata/feeds/scripts and module props. `location` follows A08 whole-record exposure; declared graphic roles are not allowed to resurrect a private selection through public fallback.
5. Equality/uniqueness rule: each effective location `factId` is unique per original qualified owner and ancestry; repeated identical facts or duplicate extensions violating A08 reject. For graphic/SEO/contact values, count local/inherited records **before** public projection, enforce max on the full effective collection, and refuse duplicates where the registry marks unique; **removing private values from public output must not mask cardinality errors**. `graphic.background` permits up to four explicit ordered layers, but duplicate exact source references within one effective background collection reject as authoring ambiguity.
6. Resolved property results retain provenance **internally** as a closed derived record `{ "property": <registered key>, "values": [<ProvenanceValue>...], "resolutionEvents": [<ResolutionEvent>...] }`. `ProvenanceValue` has exactly `data` (the fully resolved typed value), `exposure` (`public|internal`), `originOwner` (the original complete qualified EFS owner), `originLocalIndex` (zero-based original local-array index), and optional `fieldOrigins` **for location only** (map from each currently set location field name to `{ "owner": <QualifiedOwner>, "localIndex": nonnegative integer }`). `ResolutionEvent` has exactly `owner` (<QualifiedOwner>), `operation` (`inherited|added|suppressed|extended`), `localIndex` (nonnegative integer or `null` for implicit inheritance), and optional `targetFactId` for `extended`; records are ordered direct ancestry followed by local declaration order. An empty effective result may retain suppression events but no values. This is a **read-only derived diagnostic model**, not a manifest-authored field and never exposed directly in public response. Field provenance for location is A08. The only public renderer input is an explicit validated safe public projection, preserving authorized order and never substituting arbitrary ancestor values after filtering. A registry `maximum exposure` of `public` allows explicitly authored `public` or `internal`; a maximum of `internal` permits only `internal`. All first built-ins permit both classifications, but `internal` values never enter public output.
7. All property entry objects are closed and type checked. `seo` values do not override the Page's identity, route, locale or visibility; they are ordinary authorized property values. A JSON/Markdown body may not declare authoritative SEO metadata to override the registry or manifest. Direct media inside module props need not be graphic roles.

## A08 / O08 — Location fact fields, stable identity, add/extend and safe geometry

1. `location` is a D08 property, **never** an EFS node, mandatory place tier, route, locale selection signal or geocoding input. A property local `currentContext` array may contain `add` or `extend` operations. Root Entity cannot `extend` because it has no inherited value. No automatic location fact from hostname, ID, route, full locale or coordinates. Multiple facts do not create a guessed primary.
2. A new fact uses the exact closed envelope:

   `{ "operation":"add", "factId":"<technical-id>", "kind":"association"|"premises", "fields": <LocationFields>, "exposure":"public"|"internal" }`.

   `factId` uses the accepted technical-ID grammar (1–63 chars) and is stable within its original owner. The **full original owner** (not authored a second time) is the node's complete EFS lineage, derived from containment and representation locale where applicable. Identity is `(origin qualified EFS lineage, factId)`; no different record may reuse that exact pair. `kind` distinguishes conceptual association from premises; it never implies a full street address.
3. `LocationFields` is a **closed typed, nonempty** object whose allowed optional members are: `worldRegion` (short plain text ≤80); `countryCode` (ISO 3166-1 alpha-2 uppercase ASCII, no inference); `administrativeArea` (plain text ≤120); `locality` (plain text ≤120); `district` (plain text ≤120); `namedPlace` (plain text ≤160); `addressLine1` and `addressLine2` (plain text ≤200 each); `postalCode` (plain text ≤32); `coordinates` (closed object `{ "latitude": number[-90,90], "longitude": number[-180,180] }` with finite decimal WGS84 coordinates; neither elevation nor accuracy inferred). For `association`, all fields are allowed but no postal/coordinates requirement; for `premises`, partial address is allowed and no country/postal coordinate is compulsory. Empty fields object refused; omitted geographic levels are not auto-filled.
4. Extend in place with exactly:

   `{ "operation":"extend", "target": { "owner": <QualifiedOwner>, "factId":"<id>" }, "set": <NonemptyPartialLocationFields> }`.

   QualifiedOwner is a closed object with required `entity` technical ID and optional subsequent **contiguous lineage** `facet`, `site`, `page`, `locale`; if `site` is present so is `facet`, if `page` is present so are `facet/site`, if `locale` is present so are all ancestors and a full region-qualified tag. Its property owner must be an accessible **direct ancestor**, not the current node or a sibling, and it must identify exactly one presently inherited unsuppressed location fact. `set` contains only allowed typed `LocationFields` members and may modify/append those member values; it may not remove fields, change `factId`, `kind`, origin owner or `exposure`, or append a duplicate fact.
5. Apply a node's local `currentContext` operations in authored array order **only after** the inherited effective location result is established. At most one `extend` per target fact **at one node**; two conflicting same-node extensions refuse rather than last-wins. A node may add independent facts and extend inherited facts, but cannot extend its own newly added fact in the same node; use an `add` with complete intended fields instead. A target suppressed by local `inheritance: suppress` cannot be extended. Across descendants, an already-extended inherited fact retains the same original identity; its effective fields and field provenance follow the path without duplication. Missing/cross-branch/circular/suppressed target fails. Output value order stays inherited-first with in-place updated record, followed by new `add` facts.
6. Exposure is **whole-record**: an `extend` cannot supply a new `exposure`; inherited `internal` remains `internal`, never promoted to public even if changed fields are harmless. Public projection omits whole internal facts; there is no field-level publication exception. Internal provenance of each field records `(qualified owner, operation)` at its latest explicit author, while origin owner remains original, and `extend` does not erase origins of untouched fields. Consumer needing a single specific fact must use an explicit fully qualified identified selector or fail ambiguity; no declaration-order `primary` and no geographic correctness claims.
7. Geometry validation accepts only WGS84 latitude/longitude finite numbers in the ranges above; **no reprojection, reverse geocoding, distance calculation, geofence, physical-presence verification or visitor-location lookup** is implied. Unknown data is never synthesized. `null`, arbitrary custom geographic keys, nested unregistered metadata, unsupported units and fabricated defaults refuse. Future custom metadata requires a separately registered typed extension; no open map is approved.

## A09 / O09 — Graphic roles, asset source grammar, initial media formats and platform library

1. Every graphic role in A07 uses D08 additive inheritance and suppression. Initial roles and counts are exactly the A07 catalogue, with no automatic platform fallback for **any** role. Authored `source` in a graphic value is a required closed typed asset reference: `{ "namespace":"entity"|"platform", "reference":"<portable-relative-file-with-extension>" }`, no `url` or external fetch field. Module media uses the **same** typed asset reference directly without coercion into a cascading graphic role. Generic library is one installed read-only namespace, not an EFS node, alternate Entity or publisher.
2. Manifest root requires `platformAssetLibraryVersion: "1.0.0"` independent of manifest/registry/product versions. A platform asset resolves only within the **exact pinned** `platform/assets/` catalogue of the running compatible product version. The product's immutable catalogue must enumerate every available asset ID (the exact portable relative filename), hash, media class, dimensions and licensing/provenance; it cannot discover arbitrary files or substitute an "equivalent" generic asset. **No asset filename or artwork is mandated by this document**; the implementer must provide a lawful initial read-only library and publish its complete version-pinned catalogue under an Owner-reviewed asset delivery package before claiming the generic library is usable. An Installation selecting an absent library version/asset is invalid, not silently upgraded. This is a **content inventory/delivery gate for a later code-bearing package**, not permission for the agent to invent artwork.
3. Image formats admitted initially: `.png` MIME `image/png`, `.jpg`/`.jpeg` `image/jpeg`, `.webp` `image/webp`, `.avif` `image/avif`; no active SVG, GIF, external URL, script, HTML, font or unapproved container. `graphic.favicon` permits PNG only; `graphic.logo`, `banner`, `background`, `social-preview`, gallery, watermark, poster and ordinary inline media permit approved images. Video modules permit `.mp4` (`video/mp4`) with H.264/AVC video plus optional AAC-LC audio, or `.webm` (`video/webm`) with VP9 video plus optional Opus audio. Each must be verified by bounded media inspection; no alternative codec is inferred. Required timed captions are `.vtt` (`text/vtt`, UTF-8 without BOM, ≤500 KiB) in the same validated asset namespace, with safe WebVTT cue/timestamp parsing and no active HTML/script, CSS, remote reference or unsupported cue command. No remote embedded video, executable media or unapproved third-party iframe.
4. Maximum source image bytes 20 MiB, width/height 1–8192 pixels, total decoded pixels ≤32,000,000; max source video bytes 200 MiB and length ≤180 seconds (metadata and decoding must be verified); products may apply stricter operational limits **only if expressly documented and made compatible with this contract**. Reject mismatched extension/MIME/magic, malformed media, decompression bombs, active payloads and unsafe dimensions. Asset acceptance is by authoritative source bytes inspected through a bounded media processing adapter, never extension-only. A corrupted **declared** asset rejects publication, including if the declaring representation is unlisted; an unreferenced asset does not publish by presence.
5. Derived responsive variants, resized images and output URLs are generated from validated source bytes and manifest authority. They are immutable/cache-safe, provenance-linked, do not overwrite input and never become new authored source or a fallback for missing originals. No unlisted or internal media gets an auto-sitemap/navigation entry. Public use of a **cascading graphic property** requires its `exposure:public`; a **direct module media reference** does not carry that property-value exposure field and becomes public eligible only through a validated, explicitly authored public Page/module input. A module never gains access to an internal/suppressed property value or an unreferenced file. The platform library is globally reusable without copying its bytes into Entity-owned source directories; the namespace distinction is never inferred from filenames or public addresses.
6. Failed singular graphic cardinality, invalid `exposure`, wrong asset class, missing or unsafe source, unsupported format, unknown role, duplicate background source or forbidden namespace **blocks the entire candidate publication**. `suppress` plus one local value legitimately replaces a singular inherited selection. Explicitly authored platform asset usage is not automatic fallback. Direct module images require their own alt/decorative policy under O05.

## A10 / O10 — Base addresses, routes, locale selection, Unicode, link targets and discovery

1. `base.canonical` is one absolute `http:` or `https:` URL with DNS hostname/IP and optional safe prefix, no credentials, query, fragment, control character or encoded separator; trailing slash is normalized to a canonical no-trailing-slash base except origin root. Production HTTPS is strongly recommended but **HTTP remains a valid declared R00.B address**, subject to separately approved deployment security. Host syntax/port are validated; canonical host is lowercase IDNA-conformant ASCII, default ports normalized; no `Host`, forwarding header, geo-IP or provider account creates authority. `base.aliases` is an array of 0–8 distinct fully declared bases with equivalent safe structure, none equal to canonical after normalization; aliases redirect only to the authoritative canonical origin/prefix and never select a second Entity or Page. Base prefixes have 0–5 strict ASCII-safe path segments, each matching `[a-z][a-z0-9-]*`, none `.`/`..`, with no percent escapes; canonical output includes prefix **once**.
2. `Site.defaultLocale` and each representation `locale` are canonical BCP47 tags with **a mandatory region subtag** and optional script, e.g. `en-001`, `id-ID`, `de-DE`, `zh-Hans-CN`; bare `en` or `de` are never publication keys. Canonical authored case is language lowercase, script title-case, region uppercase, and public locale path is the **lowercase full tag**, including hyphen separators. Locale identity and path case are independent from Unicode Page-route case. On one Site `languagePreferences` maps request preference tag to an **already supported full locale**; map keys can be bare languages or canonical full tags, canonicalized without ambiguity. Values must be supported full locale tags within that Site and cannot be inferred from physical location. Duplicate normalized mapping keys with conflicting targets refuse.
3. A representation's `route.path` is an authored base-relative path beginning with exactly `/<lowercase full-locale-segment>/`, followed by 1–8 Page-route segments; no trailing slash other than a deliberately authored root-like special entry (which is disallowed for a representation). The first segment after the leading `/` must be the normalization of that representation's declared `locale`. Page-route segments permit NFC Unicode letters, marks and decimal digits plus internal `-` and `_`; cannot be empty, `.`/`..`, leading/trailing hyphen, control/bidi-control, slash/backslash, undecodable URI data or encoded delimiters. Locale segments are never inferred from location. The total Unicode scalar length of Page-route token portion ≤160 and each segment ≤60. HTML/JS unsafe URI parsing and ambiguous double decoding reject before matching.
4. **Unicode profile** for authored route-text normalization and case comparison is **Unicode 18.0.0**, with NFC and full Unicode Default Case Folding (not ASCII-only lowercasing) on insensitive comparisons, then NFC again; public-insensitive canonical Page-route spelling is NFC followed by Unicode 18 lowercase mapping, while sensitive claims preserve authored NFC exact case. No locale-specific tailoring is enabled in the first global route-comparison profile; this is explicit and deterministic, not an unreviewed implicit default. A future change to Unicode data or tailoring requires collision-regression tests over every authored route claim and a versioned migration/revalidation. The implementation-toolchain binding that produces exactly these results is selected in R00.E; R00.E cannot silently pick a different Unicode version. Confusable lookalikes are diagnosed using explicit UTS #39-style checks without inventing alias equivalence, and dangerous control/bidi ambiguity rejects.
5. An authored `route.caseMatching` for **public** representation is optional with default `insensitive` and allowed explicit `sensitive`. A sensitive path preserves case as canonical; wrong case returns not-found, never a guessed redirect. An effectively unlisted representation ignores public match modes and **always** matches exactly the authored NFC Unicode Page-route spelling; `caseMatching` must be omitted for unlisted. Unlisted variants have no route aliases in the first physical profile. Locale segment normalization remains independent and lowercase even on unlisted/sensitive Pages. Public aliases use authored case policy and must not point to, collide caselessly with or reveal an unlisted representation.
6. Validate a **complete derived route ledger** over canonical localized claims, every alias, all Page `entryPaths`, the configured base entry and base aliases. Alias objects have only `path` and optional `caseMatching`; their canonical path must be a full matching locale path that targets their owning representation. `entryPaths` are base-relative locale-less public entry paths, 1–8 Page-route segments, no locale segment reserved as a full representation locale; they belong to their containing qualified Page, not a guessed ID. Enforce every accepted R00.B collision rule including insensitive vs sensitive overlaps, public vs unlisted caseless overlap, Unicode normalization equivalence, alias collisions, locale-less entry conflicts, base-prefix preservation and no first-match priority. Two distinct sensitive public paths differing only in case may coexist when neither overlaps an insensitive claim; two distinct unlisted paths differing only in exact case may coexist when neither collides with public claims. Invalid claims block **whole publication** before HTTP serving.
7. `base.landing` qualified Page reference, if present, selects only an authored Page that has an eligible public localized representation. A fully unlisted Home can exist but must not be exposed; absent or unavailable public landing means base entry returns not-found. Base landing and Page `entryPaths` are locale-less **temporary preference-dependent redirect entry points**, never alternate canonical Pages. Selection order: explicit full-locale URL wins; else supported saved full-locale preference; else supported exact/mapped `Accept-Language`; else authored Site default. Missing translation applies same Page's validated `missingTranslation` policy only and redirects to an actual public authored canonical route; strict policy/no valid target yields not-found. No cross-Site/Facet/Page substitution; the current request Host/remote source can never select a different Entity, locale or Page by inference.
8. Request handling statuses: safe canonical correction and base alias normalization use a permanent canonical redirect (normally `308`) only when semantically stable; preference-dependent locale-less entry and permitted missing-translation fallback use temporary redirects (normally `302`) with `Vary`/no shared-cache protection appropriate to actually consulted inputs. Malformed/unsafe URI → `400`; unknown route/locale/representation → `404`; wrong method → `405` as applicable; untrusted/invalid host → refuse with appropriate `421`/`400`, never derive canonical authority from it; unexpected server failure → `5xx` and no silent sibling fallback. This states HTTP contract, not a requirement to choose a framework before R00.E.
9. JSON typed links use one **closed** link object from these variants: `{ "kind":"page", "target":<QualifiedRepresentation> }`, `{ "kind":"external", "url":"https://..."|"http://..." }`, `{ "kind":"email", "address":"<addr-spec>", "subject": optional plain text ≤160 }`, `{ "kind":"fragment", "id":"<existing same-Page anchor>" }`. Each link is validated before output; `page` requires full four-level qualified Page lineage plus explicit full target `locale` and actual published representation. An explicit Page link can point to an intentionally known unlisted representation but is not auto-discovered; automatic navigation/locale switch/sitemap/hreflang/x-default **never** includes unlisted. `external` can never trigger a server-side fetch, redirect forwarding from arbitrary request input or publication metadata authority. Markdown link forms map to these classified destinations through A04, without new Markdown syntax.
10. Public metadata (`canonical`, alternates, `hreflang`, `x-default`, sitemap, robots, Open Graph and assets) is derived **only** from the validated effective public representation and approved public projection, never from body front matter, guessed counterpart, unlisted content or arbitrary source paths. Unlisted direct responses always include `noindex,nofollow`, are excluded from every generated discovery surface and are **not** access control. Public `lang` is the actual full authored locale. The canonical base prefix is applied exactly once to every generated URL. Source paths and asset ownership never determine EFS identity or public address.
