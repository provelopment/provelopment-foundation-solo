The accepted `SOLO-WO-082 R01` integrated the Linux child wall-deadline kill/reap negative. The next still-open `R03.C3` gate is **actual resource-limit enforcement**, not another readback. - Fixed inherited pre-exec profile, **unchanged**: `RLIMIT_AS` soft = hard = **536870912 bytes** (512 MiB); `RLIMIT_CPU` soft = hard = **10 consumed-CPU seconds**; `setsid` before `exec`.
- Fixed bounded attempted capacity: `805306368` bytes (**768 MiB**), strictly larger than the entire RLIMIT_AS ceiling. The child must use `Vec::<u8>::new().try_reserve_exact(805306368)` or equivalently typed `Vec::<u8>::try_reserve_exact` on a new empty vector. This is a **fallible capacity reservation**, not `vec![0; N]`, not allocation-and-touch, not CPU stress, not repeated increasing allocations. It must never initialize, iterate, fill, read, write or touch any requested bytes. No `mmap`, `malloc`, allocator FFI, custom allocator, raw pointer or new `unsafe` permission.
- On real Linux, the child must first verify all four limit halves *exactly*, `pid > 0` and its own `pgid == pid`, and **only then** make the single reservation attempt. A returned `Err(TryReserveError)` is the narrowly expected **kernel/allocator refusal**. The child must produce one fixed, flushed observation line and exit normally with status zero **only when that denial is observed**. If the reservation unexpectedly succeeds, discard the reservation without touching it, emit no accepted evidence and exit through a fixed nonzero child refusal; never attempt to fill it.
- One fixed `as-parent` mode reexecutes this repository's **own trusted `solo-cli`** as `as-child`, using the **unchanged** `install_linux_child_limits_v1` pre-exec boundary. The parent enforces a finite **15 000 ms** wall deadline, caps both pipe readers to existing **1024 stdout / 512 stderr bytes**, requires a normally exited/reaped status zero, parses precisely the one child observation line, validates every value, and emits precisely one bounded `media_host_as=limit_enforced ...` line. Every failure yields no accepted evidence and a fixed typed refusal, no OS error, path, child stderr, or partial line.
- Windows and any other non-Linux target must compile ordinary parser/refusal code but both new modes must **refuse `HOST_UNSUPPORTED` (status 3)** without creating a child or attempting a reservation. Preserve public CLI byte-for-byte.
