## 3. Required R03.C2 contract — implement only byte acquisition

### 3A. Trusted root, namespaces and portable names

1. The caller must **explicitly** provide the existing `ContentRootCapability`, adopted from the operator-designated installation **`content/` directory** (or an already verified trusted directory handle). The implementation may not select a working directory, infer a root from Entity IDs or routes, adopt the repo as an asset root, scan a directory or create a fallback root. This single capability anchors both old Page reads and new Entity asset reads; it is never silently replaced. A capability to the wrong root must not be elevated into valid ownership evidence.
2. Only an already typed `AssetReferenceV1` with `namespace == AssetNamespace::Entity` is eligible. Map it to exactly the relative sequence `assets/` followed by its **unchanged authored reference segments**. These are relative to the held `content/` capability, so a concrete item such as `brand/logo.png` can only name `content/assets/brand/logo.png`. No absolute path or string prefix is accepted as proof of confinement. Neither a `pages/` locator nor a `platform` reference is reinterpreted as an Entity asset.
3. The existing graphic reference constructor enforces typed namespace, image extension and much of the reference grammar, but it does **not** by itself prove every §6.2C portable filename constraint (for example uppercase, reserved device stems, path depth and segment lengths). Implement **defense-in-depth fail-closed asset-boundary validation** before native open: lowercase ASCII portable components, `[a-z][a-z0-9._-]*`, first letter, per-component 1–80 byte ceiling, no trailing dot or space, no adjacent dots, Windows reserved basenames even with extension, exact extension, full logical path including `assets/` ≤240 bytes and ≤8 segments; no empty/dot/dot-dot, separator, colon, NUL/control, percent/encoded, URL, query, fragment, non-ASCII, drive/UNC, tilde or alias spelling. Reject; never normalize, lowercase, trim, guess or repair an authored value. Preserve the accepted domain parser and current Page source-locator grammar unchanged; a later shared grammar refactor needs separate authorization.
4. The safe adapter may call **only the current** `native::open_leaf`, `native::read_bounded` and `native::recheck`, preserving the Linux `openat2` `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_XDEV` mechanism, its immutable reflink-based transfer, and the existing Windows per-component `NtCreateFile` no-reparse, handle identity and writer-denial mechanism. A kernel/filesystem without those properties returns `Unsupported` or a safe refusal. **No** `canonicalize` + prefix check, `std::fs::read`, pre-check-follow-open, writable shared handle, Windows junction fallback, symlink dereference or less secure copying fallback.
5. `Absent` is only a positively observed missing leaf/intermediate path, **never** a benign result for a declared asset in the complete read use case. Missing, permission, IO, unsafe leaf, wrong root, symlink/junction/reparse, mount escape, hardlink, alias, unsupported snapshot and a changed source **all refuse the whole candidate** with distinguishable typed reasons where observations permit.

### 3B. Bounded immutable read and physical collision rules

1. Define the exact upper bound **`MAX_GRAPHIC_SOURCE_BYTES = 20 * 1024 * 1024`** (20 MiB) for each source. The bound applies to every extension (PNG/JPEG/WebP/AVIF), and is enforced before allocation/clone when possible and again in the native bounded read; exactly 20 MiB is allowed, **20 MiB + 1 byte is refused**, never truncated. The file must be a regular object. A zero-byte file may be faithfully acquired but is **not** therefore valid image media.
2. Require initial and final facts from the **same open handle**: identity, length, link count and observed timestamps, plus actual returned byte count. Refuse mismatch and unsupported/uncertain observations, including in-place same-size mutation when the observed timestamp changes. Do not treat byte acquisition as a globally atomic multi-file filesystem snapshot. Never claim the file cannot change after the final check.
3. Reject a file with link count other than **exactly one** (including hardlink to Page content, to another logical asset path or outside the root). Require distinct *logical Entity asset paths* to have distinct physical identities within one inventory; if different references resolve to one physical object, refuse `IdentityCollision`, even if a fake port returns a falsely benign link count. Reject inconsistent identity/content on repeat reads of the **same logical reference** within one attempt. Do **not** conflate **independently authored obligations**: the same exact filename authored by two owners is permitted only as two separately accounted obligations, each proven against the same exact physical resource and consistent bytes/identity; never deduplicate away an obligation or silently use an unrelated asset.
4. Evidence owns the acquired bytes and records the original `GraphicAssetObligationV1` (full qualified author, role, local index, exposure, typed namespace and unchanged reference), physical identity and observed exact length. Expose only bounded nonpublishing types, immutable accessors and truthful source-byte evidence. Any fingerprint must not be represented as a verified cryptographic hash, content provenance, media MIME, safe decode, rights or publication authority.
5. The inward port is a minimal Entity-reference read interface implemented by the safe adapter. Pure application policy drives **all** obligations from `GraphicAssetObligationInventoryV1`, not just the requested target, public projection or distinct filenames; it yields a complete ordered result **only if every eligible obligation succeeds**. On any failure return one typed, bounded, path/byte-safe refusal, with original declaring owner/role/index and a stable category; discard partial successes from the public result. No best-effort vector, missing-as-`None`, partial publishing or hidden fallback.

### 3C. Unimplemented Platform namespace and truthful boundary

1. `namespace: "platform"` is intentionally **unverifiable** under R03.C2. If the whole inventory contains **any** Platform obligation, whether public, internal, suppressed or unlisted, refuse the **whole** attempted complete acquisition as `PlatformUnverified` **before initiating any Entity reads**; do not omit it and return a false fully-verified Entity-only bundle. Test both Platform-only and mixed inventories, including a Platform value after an Entity one. No Platform root/catalogue/path/asset is opened, inferred or generated.
2. R03.C2 does not validate media bytes against extension/MIME/magic, image dimensions, pixels, decoders or active content; does not perform licence/provenance checks, create cryptographic catalogue hashes, derive responsive files, publish URLs, choose a fallback, or mark artwork safe. It is acceptable and required to acquire arbitrary source bytes within 20 MiB as **nonpublishing source-byte evidence** while explicitly stating that later media-validation gates must refuse malformed media. A byte-acquisition success **must never** return `media_verified = true`, `publication_authorized = true`, a fabricated catalogue record or a public-renderable value.
3. Do not change `platformAssetLibraryVersion: "1.0.0"` or imply that the platform catalogue and artwork exist. R03.C, Stage 03 and later source-media verification remain OPEN, and acceptance of R03.C2 is not authorization to publish even a correctly formatted graphic.
