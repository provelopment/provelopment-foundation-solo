**Stage II — native in-process lifetime proof, with actual host execution.** Under `#[cfg(all(test, windows))]` or an equivalently AST-proven Windows-only test module inside **`source_read_native.rs`**, use the exact generated functions. No unsafe in integration tests/other crates.

The native test suite MUST separately establish and print/classify the following (do not silently count fixture setup as a behavior test):

1. **Control: live originating writer handle.** An active writable originating file handle with a mapped view conflicts with the reader's actual `NtCreateFile` body open and causes a typed refusal, not chosen bytes or false absence. Verify the mapping really exists before triggering the reader.
2. **Decisive: persistent writable view after origin handles close.** Create the mapping, obtain the writable view, close the originating writable **file handle** (and mapping-object handle where supported) while keeping the view live; demonstrate an actual in-place *equal-length* modification through the view still works. The test must not mistake a closed file handle for a destroyed view. Report the exact Windows API success/error and by-handle read/selection outcome, using the real adapter path, not an invented fake or a newly opened writer handle.
3. **Pinned read adversary.** With that preexisting writable view still active, open the actual body through the real native `open_leaf` path, perform a view mutation after the body handle is opened and before/during `read_bounded` using a deterministic barrier or an equivalent reproducible ordering. Show whether the body handle refuses, the read refuses, or the bytes returned by the reader can change. Include pre/post source and received-bytes evidence without leaking host paths or user content. A same-length view write is essential because length checks cannot prove it safe; compare the real bytes, not just timestamps. If a reproducible in-read schedule needs a test-only seam, it must stay local to the audited native source file with no production semantic change; otherwise STOP for further authority. Do not rely solely on a sleep, timeout, success exit, a mapped view that was already unmapped, or an error before creating the view.
